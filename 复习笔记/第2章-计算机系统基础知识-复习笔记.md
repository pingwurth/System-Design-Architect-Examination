## 二、核心知识点

### 2.1 计算机系统概述

- 计算机系统 = 硬件子系统 + 软件子系统
- **冯·诺依曼结构**：运算器、控制器、存储器、输入设备、输出设备（五大部分）
- 硬件有形，软件无形；某些功能可由硬件或软件实现（如可编程逻辑）

---

### 2.2 计算机硬件

#### 2.2.2 处理器 ⭐

**指令集分类**：

| 类型 | 代表 | 特点 |
|---|---|---|
| **CISC**（复杂指令集） | Intel/AMD x86 | 指令复杂，历史遗留 |
| **RISC**（精简指令集） | ARM、Power | 指令精简，后期发展的趋势 |

**专用处理器**：
- **GPU**：数百/数千内核，并行计算，深度学习/机器学习
- **DSP**：实时数字信号处理，饱和算法，乘积累加运算
- **FPGA**：现场可编程逻辑门阵列

#### 2.2.3 存储器 ⭐⭐

**存储器层次结构（4层）**：

| 层次 | 类型 | 容量 | 特点 |
|---|---|---|---|
| **片上缓存** (L1) | SRAM | 16kB~512kB | 处理器核心内集成，速度最快 |
| **片外缓存** (L2/L3) | SRAM | 256kB~4MB | 核心外，经交换互联开关访问 |
| **主存（内存）** | DRAM | 数百MB~数十GB | 需不断充电维持数据，通过总线连接 |
| **外存** | 磁带/磁盘/光盘/Flash | MB~TB | 掉电保持数据，速度慢容量大 |

**外存数据保持年限**：
- Flash：约10年
- 光盘：数年至数十年
- 磁盘：10年以上
- 磁带：30年以上

#### 2.2.4 总线 ⭐

**按位置分类**：
- **内总线（片上总线）**：芯片内部互连
- **系统总线**：CPU、主存、I/O接口之间
- **外部总线（通信总线）**：计算机板与外部设备/计算机间互联

**总线间通过桥(Bridge)连接**，实现协议转换。

**常见总线**：
- 并行总线：PCI、PCIe、ATA(IDE)
- 串行总线：USB、SATA、CAN、RS-232、RS-485、RapidIO、以太网

**性能指标**：总线带宽、QoS、时延、抖动

### 2.3 计算机软件

#### 2.3.2 操作系统 ⭐⭐

**四大特征**：
1. **并发性** — 宏观上同时运行，微观上交替执行（单CPU）
2. **共享性** — 资源被多个进程共同使用（同时共享/互斥共享）
3. **虚拟性** — 物理实体变逻辑对应物（一对多或多对一）
4. **不确定性** — 进程执行"走走停停"，执行结果可能不唯一

**操作系统分类** ⭐：

| 类型 | 特点 | 关键考点 |
|---|---|---|
| **批处理OS** | 单道/多道；多道特点：多道、宏观并行、微观串行 | 避免CPU等待外设 |
| **分时OS** | CPU时间划分为时间片，轮流服务 | 4特点：多路性、独立性、交互性、及时性 |
| **实时OS** | 在允许时间内快速反应 | 实时控制/实时信息处理；可靠性高，交互能力要求低 |
| **网络OS** | 联网计算机共享资源 | 硬件独立性、多用户支持 |
| **分布式OS** | 多计算机无主次之分，动态分配调度 | 网络OS的更高级形式；透明性、可靠性、高性能 |
| **嵌入式OS** | 运行在嵌入式设备 | 微型化、可定制、实时性、可靠性、易移植性 |

**嵌入式OS特点**（5点）：微型化、可定制、实时性、可靠性、易移植性（HAL+BSP）

#### 2.3.3 数据库 ⭐⭐

**数据库类型**：
- 关系型数据库（传统二元关系）
- 键值数据库（Key-Value）
- 列存储数据库（Column-Based vs Row-Based）
- 文档数据库（XML/JSON/BSON，分层树状结构）
- 搜索引擎数据库

**关系数据库设计6个阶段** ⭐：
1. 需求分析
2. 概念结构设计（E-R方法：局部→全局→优化）
3. 逻辑结构设计（E-R图转换为数据模型）
4. 物理结构设计
5. 应用程序设计
6. 运行维护

**分布式数据库**：
- 完全分布式满足：分布性、逻辑相关性、场地透明性、场地自治性
- 4层结构模式：全局外层→全局概念层→局部概念层→局部内层

**大型DBMS 7个特点**：
1. 基于网络环境
2. 支持大规模应用（数千并发用户）
3. 自动锁功能
4. 高度安全性
5. 数据备份/恢复/设备镜像
6. 多种维护数据完整性手段
7. 分布式处理功能

#### 2.3.4 文件系统 ⭐

**文件物理结构**（4种）：

| 结构 | 特点 | 优缺点 |
|---|---|---|
| **连续结构** | 连续物理块 | 存取方便，但不易扩展 |
| **链接结构** | 不连续，指针链接 | 灵活，但查找慢 |
| **索引结构** | 索引表记录逻辑→物理块号 | 灵活，但索引表占空间 |
| **多物理块索引** | 链接文件/多重索引 | 适合大文件 |

**空闲空间管理方法**（4种）：
1. **空闲区表** — 适用于连续文件结构
2. **位示图** — 每位对应一个物理块（0空闲/1占用），适合各种物理结构
3. **空闲块链** — 链表结构，不需要磁盘分配表
4. **成组链接法** — UNIX采用，每100个空闲块一组

**文件共享方式**：
- **硬链接**：两个目录表目指向同一索引结点（不利于文件主删除）
- **符号链接**：建立新文件/目录映射原路径（可跨文件系统/网络）

**文件保护**：存取控制矩阵、存取控制表（UNIX三类用户：文件主/同组/其他）、用户权限表、密码

#### 2.3.6 中间件 ⭐

**中间件定义**：处于操作系统、网络和数据库之上，应用软件之下的标准化编程接口和协议。

**中间件分类**（8类）：

| 类型 | 职责 | 代表产品 |
|---|---|---|
| **通信处理(消息)中间件** | 跨平台数据传输 | IBM MQSeries、BEA eLink、TongLINK |
| **事务处理(交易)中间件** | OLTP并发事务、负载均衡 | BEA Tuxedo |
| **数据存取管理中间件** | 虚拟缓冲存取、格式转换 | — |
| **Web服务器中间件** | 扩充浏览器会话能力 | SilverStream |
| **安全中间件** | 安全保密 | 国产产品 |
| **跨平台和架构中间件** | 集成不同平台构件 | CORBA、JavaBeans、COM+ |
| **专用平台中间件** | 特定应用领域 | — |
| **网络中间件** | 网管、接入、测试 | — |

#### 2.3.7 软件构件 ⭐

**构件定义**：自包容、可复用的程序集。两个最重要特性：**自包容**与**可重用**。

**三大商用构件标准**：

| 标准 | 提出者 | 核心技术 |
|---|---|---|
| **CORBA** | OMG | ORB（对象请求代理）+ 公共服务 + 公共设施；CCM构件模型 |
| **J2EE** | Sun | RMI/IIOP；Servlet/JSP/EJB；Java跨平台 |
| **DNA 2000** | Microsoft | ASP/COM/Cluster；DCOM/COM/COM+；MTS事务处理 |

**J2EE中EJB分类**：
- **会话Bean**：维护会话
- **实体Bean**：处理事务

### 2.4 嵌入式系统及软件

#### 2.4.1 嵌入式系统组成及特点 ⭐

**组成**：嵌入式处理器 + 相关支撑硬件 + 嵌入式操作系统 + 支撑软件 + 应用软件

**8大特点**：
1. 专用性强
2. 技术融合
3. 软硬一体，软件为主
4. 比通用计算机资源少
5. 程序代码固化在非易失存储器中
6. 需专门开发工具和环境（宿主机+目标机）
7. 体积小、价格低、性价比高
8. 对安全性和可靠性要求高

#### 2.4.2 嵌入式系统分类

| 分类维度 | 类型 |
|---|---|
| 按用途 | 实时系统（强实时/弱实时） / 非实时系统 |
| 按安全性 | 安全攸关系统 / 非安全攸关系统 |

**实时系统(RTS)**：计算正确性取决于逻辑正确性**和**结果产生的时间

**安全攸关系统**：不正确功能或失效会导致人员伤亡、财产损失

#### 2.4.3 嵌入式软件组成及特点 ⭐

**5层架构**：硬件层→抽象层(HAL/BSP)→操作系统层→中间件层→应用层

**嵌入式软件6大特点**：
1. **可剪裁性** — 删除不需要的模块（静态编译、动态库）
2. **可配置性** — 根据运行状态扩展能力（数据驱动、配置表）
3. **强实时性** — 任务必须在Deadline内完成
4. **安全性(Safety)** — 规定条件下不发生事故（DO-178 A~E五级）
5. **可靠性** — 规定条件下执行功能的能力（安全攸关系统10⁷~10⁹）
6. **高确定性** — 运行时间、状态和行为预先设计好

#### 2.4.4 安全攸关软件（DO-178B）⭐

**DO-178B核心三要素**：目标、过程、数据

**软件安全等级（A~E）**：

| 等级 | 失效状态 | 目标数量 |
|---|---|---|
| A级 | 灾难性的 | 66 |
| B级 | 危害性的 | 65 |
| C级 | 严重的 | 56 |
| D级 | 不严重的 | 28 |
| E级 | 没有影响的 | 0 |

**软件生命周期三大过程**：
1. **软件计划过程** — 策划和协调
2. **软件开发过程** — 需求→设计→编码→集成
3. **软件综合过程** — 验证→配置管理→质量保证→审定联络

**DO-178 vs CMMI**：
- DO-178：适航审定视角，关注项目软件质量对安全性影响；目标更清晰，要求更具体
- CMMI：过程改进视角，关注组织整体软件能力提升；覆盖个人/项目/组织三层

### 2.5 计算机网络

#### 2.5.1 网络基本概念

**网络发展4阶段**：
1. 诞生（远程联机系统）→ 2. 形成（ARPANET，IMP通信子网）→ 3. 互联互通（TCP/IP + OSI）→ 4. 高速发展（Internet）

**网络5大功能**：数据通信、资源共享、管理集中化、分布式处理、负荷均衡

**性能指标** ⭐：

| 指标 | 含义 |
|---|---|
| **速率** | 数据率/比特率 (b/s) |
| **带宽** | 信号频带宽度(Hz) 或 最高数据率(b/s) |
| **吞吐量** | 单位时间通过的数据量，受带宽限制 |
| **时延** | 发送时延+传播时延+处理时延+排队时延 |
| **往返时间(RTT)** | 发送到收到确认的总时间 |
| **利用率** | 信道利用率 / 网络利用率 |

#### 2.5.2 通信技术 ⭐

**香农公式**：C = B × log₂(1 + S/N)
- C: 信道容量(b/s)，B: 信号带宽(Hz)，S/N: 信噪比

**信号变换流程**：
- 发信机：信源编码→信道编码→交织→脉冲成形→调制
- 收信机：解调→采样判决→去交织→信道译码→信源译码

**复用技术**：TDM(时分)、FDM(频分)、CDM(码分)
**多址技术**：TDMA、FDMA、CDMA（复用技术是基础）

**5G关键技术**：OFDM优化波形、可扩展OFDM间隔、大规模MIMO、毫米波、频谱共享、LDPC码/Polar码

#### 2.5.3 网络技术 ⭐

**局域网拓扑**：

| 拓扑 | 优点 | 缺点 |
|---|---|---|
| **星状** | 速度快、建网易、便于管理 | 中心结点故障导致全网瘫痪 |
| **树状** | 成本低、扩充方便 | 非叶结点故障影响全网 |
| **总线** | 结构简单 | 总线故障影响所有结点 |
| **环形** | 地位相同、无信道选择 | 任一结点故障导致瘫痪 |
| **网状** | 抗毁性好 | 布线繁琐、成本高 |

**以太网关键考点**：
- IEEE 802.3标准
- 最小帧长：**64字节**（CSMA/CD算法限制）
- 数据域上限：通常1500字节
- 流量控制：半双工用反压(Back-Pressure)，全双工用IEEE 802.3x PAUSE帧

**OSI 7层模型 vs TCP/IP 4层模型** ⭐⭐：

| OSI 7层 | TCP/IP 4层 | 关键协议 |
|---|---|---|
| 应用层 | 应用层 | FTP、Telnet、SMTP、NFS、SNMP、HTTP |
| 表示层 | ↑ | — |
| 会话层 | ↑ | — |
| 传输层 | 传输层 | TCP、UDP |
| 网络层 | 网际层 | IP、ICMP、ARP、RARP |
| 数据链路层 | 网络接口层 | IEEE 802.3、FDDI、PPP/SLIP |
| 物理层 | ↑ | RS-232、RS-449、X.21 |

**路由协议分类**：
- **IGP（内部网关协议）**：距离矢量算法 / 链路状态算法（OSPF、IS-IS）
- **EGP（外部网关协议）**：BGP

#### 2.5.4 组网技术 — 网络设备工作层级 ⭐

| 设备 | OSI层级 | 功能 |
|---|---|---|
| **集线器** | 物理层 | 数据转送到所有其他端口 |
| **中继器** | 物理层 | 再生信号 |
| **网桥** | 数据链路层 | 连接不同介质/分支 |
| **交换机** | 数据链路层 | 基于MAC地址转发，隔离冲突域 |
| **路由器** | 网络层 | 路由选择、异种网络互连 |
| **防火墙** | 多层 | 安全规则过滤 |

**交换机基本功能**：转发路径学习、数据转发、数据泛洪（目的MAC未知时）、链路地址更新（300s）

**生成树协议(STP)**：解决交换网络中的环路问题

### 2.6 计算机语言

#### 2.6.2 语言分类 ⭐

| 语言类型 | 特点 |
|---|---|
| **机器语言** | 二进制，直接执行，速度快，不可移植 |
| **汇编语言** | 符号化机器语言，面向机器，效率高，需汇编程序翻译 |
| **高级语言** | 与架构无关，可移植性好（C/C++/Java/Python等） |
| **建模语言** | UML（统一建模语言） |
| **形式化语言** | Z语言、VDM、CCS、CSP等 |

**机器语言指令格式**：操作码 + 地址码
- 三地址/二地址/单地址/零地址/可变地址

**汇编语言三种语句**：指令语句（产生机器码）、伪指令语句（不产生机器码）、宏指令语句

#### UML ⭐⭐

**UML 3个要素**：基本构造块（事物+关系）、图、公用机制

**4种事物**：
- 结构事物（类、接口、协作、用例、构件、制品、结点）
- 行为事物（交互、状态机、活动）
- 分组事物（包）
- 注释事物（注解）

**4种关系**：
- **依赖**（虚线箭头）：一个变化影响另一个
- **关联**（实线）：对象间连接（含聚集）
- **泛化**（实线空心箭头）：特殊/一般关系（继承）
- **实现**（虚线空心箭头）：类元间契约

**UML 2.0 共13种图**：
- 类图、对象图、用例图、序列图、通信图、状态图、活动图、构件图、部署图、组合结构图、包图、交互概览图、计时图

**UML 5种视图** ⭐：

| 视图 | 关注点 | 主要图 |
|---|---|---|
| **用例视图**（中心） | 功能需求 | 用例图 |
| **逻辑视图** | 系统内部功能实现 | 类图、对象图、状态图、顺序图、合作图、活动图 |
| **进程视图** | 并发性、通信同步 | 状态图、顺序图、合作图、活动图、构件图、配置图 |
| **实现视图** | 代码构件组织 | 构件图 |
| **部署视图** | 软硬件物理架构 | 配置图 |

#### 形式化语言

**4大流派**：
1. 公理方法（Floyd、Hoare、Dijkstra）— 前置/后置条件
2. 集合论+谓词演算（meta-IV、Z语言）— VDM维也纳方法
3. 代数规格说明（OBJ、ACT）
4. 进程描述语言（CSP、CCS）

**Z语言**：基于集合论和数理逻辑，"状态-操作"风格，强类型系统

### 2.7 多媒体

#### 多媒体4个重要特征：
1. **多维化** — 媒体多样化
2. **集成性** — 设备集成 + 信息集成
3. **交互性** — 变被动为主动
4. **实时性** — 音视频时间特性

#### 视音频压缩 ⭐

| 类型 | 特点 | 常见格式 |
|---|---|---|
| **无损压缩** | 压缩前后完全一致，RLE行程编码 | WAV、PCM、FLAC、APE、TTA |
| **有损压缩** | 丢失不敏感信息，不可恢复 | MP3、WMA、OGG |

**压缩标准**：
- 静态图像：**JPEG**、JPEG 2000
- 动态图像：**MPEG**系列（MPEG-1/2/4/7/21）
- 视频编解码：**H.26L**（H.264）

**VR/AR 4种类型**：桌面式VR、分布式VR、沉浸式VR、增强式VR(AR)

| **网络** | 设备级/网络级/应用级/用户级性能指标、吞吐量 |

#### 2.9.3 性能设计 — 阿姆达尔定律 ⭐⭐

**核心思想**：性能改进程度取决于增强方式被使用的频率（占总执行时间的比例）

**公式**：

```
总加速比 = 1 / [(1 - 增强比例) + 增强比例/增强加速比]
```

**关键理解**：
- 增强比例：能被改进部分在总执行时间中的占比（≤1）
- 增强加速比：使用增强方式后的速度提升倍数
- 即使增强加速比无穷大，总加速比也受限于增强比例（上限 = 1/(1-增强比例)）

#### 2.9.4 性能评估

## 三、易混淆点对比

| 对比项 | 区别 |
|---|---|
| CISC vs RISC | CISC指令复杂(x86)；RISC指令精简(ARM)，是发展趋势 |
| SRAM vs DRAM | SRAM不需充电刷新，速度快容量小（缓存）；DRAM需不断充电（内存） |
| 并发 vs 并行 | 并发是宏观同时、微观交替（单CPU）；并行是多CPU真正同时执行 |
| 分时OS vs 实时OS | 分时OS重交互（时间片轮转）；实时OS重可靠性（快速响应） |
| 硬链接 vs 符号链接 | 硬链接指向索引结点（不可跨文件系统）；符号链接指向路径（可跨网络） |
| OSI 7层 vs TCP/IP 4层 | OSI是理论模型；TCP/IP是实际使用的协议栈 |
| 交换机 vs 路由器 | 交换机工作在数据链路层(MAC)；路由器工作在网络层(IP) |
| DO-178 vs CMMI | DO-178关注项目安全性（适航）；CMMI关注组织能力成熟度（过程改进） |
| 霍尔 vs 切克兰德 | 霍尔是硬系统方法论（最优化）；切克兰德是软科学方法论（比较与探寻） |
