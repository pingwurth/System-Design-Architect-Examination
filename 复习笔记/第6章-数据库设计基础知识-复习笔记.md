# 第6章 数据库设计基础知识 - 考前复习笔记

## 章节概述

本章覆盖数据库从基本概念到设计实施的全流程。核心考点集中在：**三级模式、关系代数运算、规范化理论（1NF→BCNF）、数据库设计六阶段、E-R图转换**。NoSQL 近年出题频率上升。

---

## 一、数据库基本概念 ⭐⭐

### 1.1 核心术语

| 术语 | 定义 |
|------|------|
| **数据（Data）** | 描述事物的符号记录 |
| **信息（Information）** | 现实世界事物存在方式或状态的反映 |
| **数据库（DB）** | 统一管理的、长期存储的、有组织的相关数据集合 |
| **DBMS** | 数据库管理系统，核心软件，提供数据定义/操纵/运行管理/维护功能 |
| **DBS（数据库系统）** | 包含 DB + DBMS + 应用程序 + DBA 的完整系统 |

> **关系**：DBS ⊃ DBMS ⊃ DB

### 1.2 数据管理技术发展阶段 ⭐

| 阶段 | 特点 | 缺点 |
|------|------|------|
| **人工管理** | 数据不保存；数据与程序一一对应；无管理软件 | 依赖性强、数据冗余 |
| **文件系统** | 数据可长期保存；逻辑/物理结构有区别；文件组织多样化 | 数据冗余大、不一致性、数据孤立 |
| **数据库系统** | 采用数据模型；数据独立性高；DBMS统一管理 | — |

### 1.3 数据模型 ⭐⭐

**数据模型三要素**：数据结构（静态）、数据操作（动态）、数据约束条件

| 模型类型 | 结构 | 特点 |
|----------|------|------|
| **层次模型** | 树形结构 | 根以外每个节点有且仅有一个双亲；上层到下层是1:N |
| **网状模型** | 网络结构 | 允许多个双亲；允许节点无双亲；不能直接表示M:N |
| **关系模型** | 表格结构 | 最常用；描述一致性好；简单灵活 |
| **面向对象模型** | 对象结构 | 支持复杂数据类型 |

> 层次模型是网状模型的特例

### 1.4 DBMS 功能与特点 ⭐

**六大功能**：
1. 数据定义（DDL）
2. 数据库操作（DML）
3. 数据库运行管理（并发控制、安全性、完整性、事务管理、故障恢复）
4. 数据组织、存储和管理
5. 数据库建立和维护
6. 其他功能（通信、数据转换）

**三大特点**：
1. 数据结构化且统一管理
2. 较高的数据独立性（物理独立性 + 逻辑独立性）
3. 数据控制功能（安全性、完整性、并发控制、故障恢复）

### 1.5 数据库三级模式 ⭐⭐⭐（必考）

```
┌─────────────────────────────────────┐
│  外模式（视图层/用户模式/子模式）     │ ← 用户看到的部分数据
├─────────────────────────────────────┤
│  概念模式（模式/逻辑层）             │ ← 全部数据的逻辑结构
├─────────────────────────────────────┤
│  内模式（存储模式/物理层）           │ ← 数据物理存储方式
└─────────────────────────────────────┘
```

| 模式 | 别称 | 描述内容 | 对应 |
|------|------|----------|------|
| **外模式** | 用户模式、子模式 | 用户需要的部分数据 | 视图层 |
| **概念模式** | 模式 | 全部数据的逻辑结构（不涉及存储） | 逻辑层 |
| **内模式** | 存储模式 | 数据的物理存储方式 | 物理层 |

- **两级映像**：外模式/模式映像（逻辑独立性）+ 模式/内模式映像（物理独立性）
- 概念模式相对稳定，实例相对变动

## 二、关系数据库 ⭐⭐⭐

### 2.1 基本术语

| 术语 | 定义 |
|------|------|
| **属性** | 描述事物的特征 |
| **域** | 属性取值范围（必须是原子数据 → 1NF） |
| **目/度** | 关系中属性的个数 |
| **候选码** | 能唯一标识元组的属性或属性组 |
| **主码** | 从多个候选码中选定的一个 |
| **主属性** | 包含在任何候选码中的属性 |
| **非主属性** | 不包含在任何候选码中的属性 |
| **外码** | 不是本关系的码，但是其他关系的码 |
| **全码** | 所有属性组合起来才是候选码 |

### 2.2 关系完整性约束 ⭐⭐

| 约束类型 | 定义 | 示例 |
|----------|------|------|
| **实体完整性** | 主键唯一且非空 | 每个表必须有主键 |
| **参照完整性** | 外码值必须是被参照关系主码的有效值或空值 | 员工部门号必须是存在的部门 |
| **用户定义完整性** | 特定应用的语义约束 | 账户号在100000-999999之间 |

### 2.3 关系代数运算 ⭐⭐⭐

#### 基本运算（5种）

| 运算 | 符号 | 方向 | 描述 |
|------|------|------|------|
| **并** | R∪S | 水平 | 属于R或属于S的元组 |
| **差** | R-S | 水平 | 属于R但不属于S的元组 |
| **笛卡尔积** | R×S | 水平 | R的元组与S的元组的所有组合（n+m列） |
| **投影** | π | 垂直 | 选择若干属性列组成新关系 |
| **选择** | σ | 水平 | 选择满足条件的元组 |

#### 扩展运算

| 运算 | 描述 |
|------|------|
| **交** | R∩S = R-(R-S)，属于R又属于S |
| **θ连接** | 笛卡尔积中选取满足θ条件的元组 |
| **等值连接** | θ为"="时的连接 |
| **自然连接** | 等值连接+去掉重复属性列（水平+垂直方向） |
| **除** | 同时从水平和垂直方向运算；X的象集包含S在Y上的投影 |
| **外连接** | 左外/右外/全外连接，处理缺失信息（用null填充） |
| **聚集函数** | sum, avg, count, min, max |

> **自然连接 vs 笛卡尔积**：自然连接要去掉重复属性；如果没有重复属性，自然连接退化为笛卡尔积
> **自然连接**是唯一同时从水平和垂直方向运算的连接方式

### 2.4 规范化理论 ⭐⭐⭐（核心考点）

#### 函数依赖

| 类型 | 定义 | 符号 |
|------|------|------|
| **函数依赖** | X决定Y：X相同则Y必相同 | X→Y |
| **完全函数依赖** | Y依赖X，且不依赖X的任何真子集 | X↠Y（F） |
| **部分函数依赖** | Y依赖X，但存在X的真子集也能决定Y | X↠Y（P） |
| **传递函数依赖** | X→Y, Y→Z, 且Y不→X, Y≠X | Z传递依赖于X |

#### 多值依赖

- 给定(X,Z)值，Y的值只由X决定，与Z无关
- 性质：对称性、传递性；函数依赖是多值依赖的特殊情况

#### 范式层次 ⭐⭐⭐

| 范式 | 条件 | 消除的依赖 |
|------|------|------------|
| **1NF** | 每个分量不可再分 | — |
| **2NF** | 1NF + 非主属性完全依赖于码 | 消除非主属性对码的**部分函数依赖** |
| **3NF** | 2NF + 无非主属性对码的传递依赖 | 消除非主属性对码的**传递函数依赖** |
| **BCNF** | 3NF + 消除主属性对码的部分和传递依赖 | 消除**主属性**对码的部分和传递依赖 |
| **4NF** | BCNF + 无非平凡且非函数依赖的多值依赖 | 消除非平凡的多值依赖 |

> **层次关系**：1NF ⊂ 2NF ⊂ 3NF ⊂ BCNF ⊂ 4NF
> **关键区分**：
> - 1NF→2NF：消除**部分依赖**（非主属性对码）
> - 2NF→3NF：消除**传递依赖**（非主属性对码）
> - 3NF→BCNF：消除**主属性**的部分和传递依赖
> - 只考虑函数依赖时，最高到 **BCNF**；考虑多值依赖时，最高到 **4NF**

#### 1NF 的四个问题

1. **冗余度大**
2. **修改操作不一致**
3. **插入异常**（部分主码为空时无法插入）
4. **删除异常**（删除数据时丢失实体信息）

## 三、数据库设计 ⭐⭐⭐

### 3.1 设计六阶段 ⭐⭐⭐（必记顺序）

```
需求分析 → 概念结构设计 → 逻辑结构设计 → 物理结构设计 → 实施 → 运行维护
```

| 阶段 | 核心任务 | 输出/工具 |
|------|----------|-----------|
| **需求分析** | 调查业务、收集数据和处理要求 | 数据流图、数据字典 |
| **概念结构设计** | 独立于DBMS的概念模型 | E-R图 |
| **逻辑结构设计** | 转换为DBMS支持的数据模型 | 关系模式、视图 |
| **物理结构设计** | 确定存储结构和访问方式 | 索引、存储方案 |
| **实施** | 建库、加载数据、试运行 | DDL脚本、数据库 |
| **运行维护** | 监测性能、备份恢复、重组重构 | — |

### 3.2 需求分析

- 分析方法：**自顶向下**（结构化分析SA）和**自底向上**
- 收集三方面要求：**信息要求**、**处理要求**、**系统要求**

### 3.3 概念结构设计 ⭐⭐

**E-R方法**：实体、属性、联系

**三种抽象机制**：
- **分类**：按共同特征定义类型
- **聚集**：定义类型的属性
- **概括**：由已知类型定义新类型（超类→子类，"is subset of"）

**设计步骤**：选择局部应用→逐一设计分E-R图→E-R图合并

**分E-R图合并时的三类冲突** ⭐：

| 冲突类型 | 描述 |
|----------|------|
| **属性冲突** | 属性类型、取值范围、数据单位不一致 |
| **命名冲突** | 同义不同名或同名不同义 |
| **结构冲突** | 同一实体属性不同；同一对象一处是实体另一处是属性 |

**合并优化**：实体类型合并（1:1或1:*联系）、冗余属性消除、冗余联系消除

### 3.4 逻辑结构设计 ⭐⭐⭐

#### E-R图→关系模式转换规则 ⭐⭐⭐

| 联系类型 | 转换规则 |
|----------|----------|
| **1:1联系** | 归并到任一方，增加对方主码和联系属性 |
| **1:N联系** | 归并到**多方**，增加一方主码和联系属性 |
| **M:N联系** | **必须**转换为独立关系模式，码为多方主码组合 |

#### 关系模式规范化步骤

1. 确定数据依赖
2. 确定范式等级
3. 不满足则分解到3NF或BCNF
4. 评价与修正（可能需要反规范化）

#### 反规范化 ⭐

**目的**：提高读操作（查询）性能

**常见操作**：冗余列、派生列、表重组、表分割（水平分割/垂直分割）

**代价**：数据冗余 → 需用应用程序同步/批量处理同步/触发器同步解决不一致

### 3.5 物理结构设计 ⭐

三大任务：**确定数据分布** + **确定存储结构** + **确定访问方式**

#### 聚簇索引建立原则

1. 聚簇码值相对稳定
2. 表主要用于查询
3. 每个聚簇码值的平均元组数适中

#### 不宜建索引的情况

- 太小的表
- 经常更新的属性/表
- 属性值很少的表
- 过长的属性
- 大文本/多媒体数据类型
- 很少出现在查询条件中的属性

#### 宜建索引的情况

- 主码/外码
- 以查询为主或只读的表
- 范围查询、聚集函数、排序输出的属性

### 3.6 实施阶段

1. 用 DDL 建立实际数据库结构
2. 数据加载（手工录入/数据转换工具）
3. 试运行和评价（测试功能 + 测试运行效率）

### 3.7 运行维护

- **性能监测与改善**
- **备份与故障恢复**
- **数据库重组**：不改变结构，去除碎片和废弃空间
- **数据库重构**：修改表结构/视图

## 四、应用程序与数据库交互 ⭐

| 方式 | 特点 | 代表 |
|------|------|------|
| **库函数接口（OCI）** | 最底层高级语言接口；强依赖特定数据库 | Oracle OCI |
| **嵌入式SQL** | SQL直接写入高级语言源码；需预编译器 | SQL86/SQL89标准 |
| **通用数据接口（ODBC）** | 统一接口访问异构数据库；不依赖特定DBMS | ODBC, JDBC, ADO.NET |
| **ORM** | 对象-关系映射；程序员只需关心对象 | Hibernate, MyBatis, JPA |

> **ODBC 发展脉络**：ODBC → DAO（本地桌面）→ RDO（远程）→ ADO（通用）→ ADO.NET
> **ORM框架对比**：Hibernate（全自动）vs MyBatis（半自动）vs JPA（Java标准注解）

## 五、NoSQL 数据库 ⭐

### 5.1 四种类型

| 类型 | 数据模型 | 典型产品 | 适用场景 |
|------|----------|----------|----------|
| **列式存储** | 按列组织存储 | Cassandra, HBase, Riak | 分布式海量数据 |
| **键值对** | 哈希表（键→值） | Redis, Voldemort | 简单高速读写 |
| **文档型** | JSON等半结构化文档 | MongoDB, CouchDB | 网页等复杂数据 |
| **图数据库** | 图形模型 | Neo4J, InfoGrid | 社交网络、生物信息网络 |

### 5.2 NoSQL 共同特征

- **易扩展**（无关系型特性）
- **大数据量高性能**（结构简单）
- **灵活的数据模型**（无需预定义字段）
- **高可用**（复制模型实现）

### 5.3 NoSQL 四层体系框架

```
接口层（Rest/Thrift/MapReduce/Get-Put/特定语言API）
    ↑
数据逻辑模型层
    ↑
数据分布层（CAP支持/多数据中心/动态部署）
    ↑
数据持久层（内存/硬盘/内存+硬盘/可插拔）
```

### 5.4 NoSQL 适用场景

- 数据模型比较简单
- 需要灵活性更强的IT系统
- 对数据库性能要求较高
- 不需要高度的数据一致性

## 易混淆点对比

| 对比项 | 区别要点 |
|--------|----------|
| DB vs DBMS vs DBS | DB是数据集合，DBMS是管理软件，DBS是完整系统 |
| 外模式 vs 概念模式 vs 内模式 | 用户视角 vs 全局逻辑 vs 物理存储 |
| 选择 vs 投影 | 选择=行的筛选（水平）；投影=列的选取（垂直） |
| 自然连接 vs 等值连接 | 自然连接自动去掉重复属性列；等值连接保留 |
| 部分依赖 vs 传递依赖 | 部分=依赖码的真子集；传递=A→B→C的链式 |
| 2NF vs 3NF | 2NF消除部分依赖；3NF消除传递依赖 |
| BCNF vs 3NF | BCNF还消除主属性的部分/传递依赖 |
| 聚簇 vs 普通索引 | 聚簇改变物理存储顺序；普通索引不改变 |
| 重组 vs 重构 | 重组不改变结构（去碎片）；重构修改表/视图结构 |
| OCI vs ODBC | OCI是特定数据库底层接口；ODBC是通用标准接口 |
| ORM vs 嵌入SQL | ORM隐藏SQL细节用对象操作；嵌入SQL直接写SQL |
