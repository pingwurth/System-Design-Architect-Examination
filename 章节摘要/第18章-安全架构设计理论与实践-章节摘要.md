## 一、安全架构概述

### 1.1 信息安全面临的威胁 ⭐

**三大安全属性**：可用性、完整性、机密性、可控性、不可抵赖性

**威胁分类（按攻击对象）**：

| 威胁类型 | 说明 | 典型例子 |
|----------|------|----------|
| 物理安全威胁 | 对设备的威胁 | 自然灾害、电源故障、设备被盗 |
| 通信链路威胁 | 对传输线路的威胁 | 搭线窃听、信号干扰 |
| 网络安全威胁 | 利用网络开放性 | 网络入侵、DDoS |
| 操作系统威胁 | 对系统平台的威胁 | 木马、陷阱门、BIOS万能密码 |
| 应用系统威胁 | 对业务系统的威胁 | 应用层木马、陷阱门 |
| 管理系统威胁 | 人员管理疏忽 | 拷贝/拍照/抄录盗取信息 |

**19种常见安全威胁速记** ⭐：

| 编号 | 威胁 | 关键词 |
|------|------|--------|
| 1 | 信息泄露 | 非授权实体获取信息 |
| 2 | 破坏完整性 | 非授权增删修改 |
| 3 | 拒绝服务 | 合法访问被阻止 |
| 4 | 非法使用 | 非授权访问资源 |
| 5 | 窃听 | 搭线监听/电磁泄漏 |
| 6 | 业务流分析 | 统计分析通信频度/流向 |
| 7 | 假冒 | 非法冒充合法用户 |
| 8 | 旁路控制 | 利用安全缺陷绕过防线 |
| 9 | 授权侵犯 | 内部攻击，越权使用 |
| 10 | 特洛伊木马 | 隐藏恶意程序段 |
| 11 | 陷阱门 | 特定输入触发违规 |
| 12 | 抵赖 | 否认发布/伪造消息 |
| 13 | 重放 | 截获合法数据重新发送 |
| 14 | 计算机病毒 | 传染+破坏功能 |
| 15 | 人员渎职 | 内部人为泄露 |
| 16 | 媒体废弃 | 从废弃介质获取信息 |
| 17 | 物理侵入 | 绕过物理控制 |
| 18 | 窃取 | 令牌/身份卡被盗 |
| 19 | 业务欺骗 | 伪系统骗取敏感信息 |

### 1.2 安全架构定义 ⭐

**三道安全防线**：

| 防线 | 定义 | 目标 |
|------|------|------|
| **产品安全架构** | 产品安全质量属性的组成及关系 | 不依赖外部防御，从源头打造安全产品 |
| **安全技术体系架构** | 安全技术体系的组成及关系 | 构建通用安全技术基础设施，系统性增强防御 |
| **审计架构** | 独立审计部门的风险发现能力 | 覆盖所有风险（含安全风险） |

**安全三要素（CIA）**：
- **可用性（Availability）**：防止数据和资源丢失
- **完整性（Integrity）**：防止未授权修改
- **机密性（Confidentiality）**：防止未授权披露

## 二、安全模型 ⭐⭐⭐（高频考点）

### 2.1 状态机模型

**核心思想**：无论处于何种状态都是安全的系统。用状态变量描述系统状态，用转换规则描述变量变化。

**工作原理**：
1. 状态变量默认值必须安全
2. 用户试图使用默认值
3. 系统检查主体身份验证
4. 系统确保变更不会使系统置于不安全状态
5. 允许变量值变更（状态改变）

**关键**：从安全状态启动，所有迁移保持安全状态。

### 2.2 BLP模型（Bell-LaPadula）⭐⭐⭐

**核心**：**机密性模型**，第一个提供分级数据机密性保障的安全策略模型。

**安全级别**：绝密 > 机密 > 秘密

**核心规则** ⭐：

| 规则 | 内容 | 记忆口诀 |
|------|------|----------|
| **简单安全规则** | 低级别主体**不能读**高级别客体 | **No Read Up（不上读）** |
| **星属性规则** | 高级别主体**不能写**低级别客体 | **No Write Down（不下写）** |
| **强星属性规则** | 不允许对另一级别读写 | 同级才能读写 |
| **自主安全规则** | 用访问控制矩阵定义自由存取控制 | DAC补充 |

**一句话记忆**：BLP保证信息只向上读、只向下写 → 防止机密泄露到低级别

### 2.3 Biba模型 ⭐⭐⭐

**核心**：**完整性模型**，解决数据完整性问题（与BLP互补）。

**完整性三目标**：
1. 保护数据不被未授权用户更改
2. 保护数据不被授权用户越权修改
3. 维持数据内部和外部一致性

**核心规则** ⭐：

| 规则 | 内容 | 记忆口诀 |
|------|------|----------|
| **星完整性规则** | 低完整性主体**不能写**高完整性客体 | **No Write Up（不上写）** |
| **简单完整性规则** | 高完整性主体**不能读**低完整性客体 | **No Read Down（不下读）** |
| **调用属性规则** | 低完整性主体**不能调用**高完整性客体的程序/服务 | 不上调用 |

**BLP vs Biba 对比** ⭐⭐⭐（必考）

| 对比项 | BLP | Biba |
|--------|-----|------|
| 保护目标 | **机密性** | **完整性** |
| 核心关注 | 防止信息泄露 | 防止数据被篡改 |
| 读规则 | 不上读（No Read Up） | 不下读（No Read Down） |
| 写规则 | 不下写（No Write Down） | 不上写（No Write Up） |
| 信息流方向 | 只能向上流动 | 只能向下流动 |
| 安全级别 | 基于敏感度分级 | 基于完整性分级 |

### 2.4 Clark-Wilson模型（CWM）⭐⭐

**核心**：**完整性模型**，实现事务处理机制，常用于**银行系统**。

**关键概念**：

| 概念 | 缩写 | 说明 |
|------|------|------|
| 受约束数据项 | **CDI** | 需要完整性保护的客体 |
| 非约束数据项 | **UDI** | 不需要完整性保护的客体 |
| 完整性验证过程 | **IVP** | 确认数据处于有效状态 |
| 转换过程 | **TP** | 将数据从一种有效状态改变到另一种 |

**CWM三大特征** ⭐：
1. **Subject/Program/Object 三元素**：Subject只能通过Program访问Object
2. **职责分离（Separation of Duty）**：要害功能分给2个以上Subject完成
3. **审计能力（Auditing）**：要求具备审计能力

### 2.5 Chinese Wall模型 ⭐⭐

**核心**：防止**利益冲突**，应用于多边安全系统（最初为投资银行设计）。

**模型结构**：

```
利益冲突类（COI）
  └── 公司数据集（CD）
        └── 单个信息（C）
```

- 每个C只对应一个CD
- 每个CD只对应一个COI
- 一个COI可包含多个CD

**安全规则** ⭐：
1. 可访问：与主体曾访问过的信息属于**同一公司数据集**（墙内信息）
2. 可访问：属于**完全不同的利益冲突组**
3. 写操作前提：主体**未对任何其他公司数据集**进行过访问

**定理1**：访问过一个客体后，只能访问同一公司数据集或不同利益组的客体
**定理2**：在一个利益冲突组中，最多只能访问一个公司数据集

**Chinese Wall = DAC + MAC混合策略**：
- DAC属性：银行家可选择为谁工作
- MAC属性：一旦选定，只能为该客户工作

### 2.6 五大模型综合对比 ⭐⭐⭐

| 模型 | 保护目标 | 核心机制 | 典型应用 |
|------|----------|----------|----------|
| **状态机模型** | 所有状态安全 | 状态变量+转换规则 | 理论基础 |
| **BLP** | 机密性 | 不上读、不下写 | 军事/政府保密 |
| **Biba** | 完整性 | 不下读、不上写 | 数据完整性保护 |
| **CWM** | 完整性（事务） | CDI/UDI + IVP + TP + 职责分离 | 银行系统 |
| **Chinese Wall** | 利益冲突 | 公司数据集 + 利益冲突组 | 投资银行/咨询 |

## 五、OSI网络安全体系架构 ⭐⭐

### 5.1 OSI安全体系结构

**标准**：ISO 7498-2 / GB/T 9387.2-1995

**核心内容**：5大类安全服务 + 8类安全机制 + OSI安全管理

#### 5类安全服务 ⭐

| 服务 | 说明 |
|------|------|
| **鉴别（Authentication）** | 实体身份验证 |
| **访问控制** | 控制资源访问权限 |
| **数据机密性** | 保护数据不被未授权泄露 |
| **数据完整性** | 保护数据不被未授权修改 |
| **抗抵赖性** | 提供事件/行为的不可否认证据 |

#### 安全服务在各层的配置 ⭐

| OSI层 | 适合配置安全服务 |
|-------|-----------------|
| 物理层 | ✅ 适合 |
| 数据链路层 | 可配置 |
| 网络层 | ✅ 适合 |
| 传输层 | ✅ 适合 |
| 会话层 | ❌ 不适合 |
| 表示层 | 可配置 |
| 应用层 | ✅ 适合 |

> **注意**：会话层是唯一不适合配置安全服务的层。

### 5.2 深度防御体系架构 ⭐

**三种防御方式**：

| 防御方式 | 说明 |
|----------|------|
| **多点技术防御** | 防御核心区域：网络和基础设施、边界、计算环境 |
| **分层技术防御** | 多层防御机制，每层代表唯一障碍（如嵌套防火墙+入侵检测） |
| **支撑性基础设施** | 公钥基础设施（PKI）+ 检测和响应基础设施 |

### 5.3 认证框架

**鉴别方式**（5种）：
1. 已知的（口令）
2. 拥有的（IC卡、令牌）
3. 不改变的特性（生物特征）
4. 可信第三方建立的鉴别（递推）
5. 环境（主机地址等）

**鉴别服务阶段**：安装 → 修改 → 分发 → 获取 → 传送 → 验证 → 停活 → 重激活 → 取消安装

### 5.4 访问控制框架

**四个核心组件**：

| 组件 | 缩写 | 功能 |
|------|------|------|
| 访问控制信息 | ACI | 用于访问控制目的的任何信息 |
| 访问控制判决信息 | ADI | 做判决时可用的ACI |
| 访问控制判决功能 | ADF | 做出允许/禁止的判决 |
| 访问控制实施功能 | AEF | 确保只有允许的访问被执行 |

### 5.5 机密性框架

**机密性机制**：
- 通过**禁止访问**提供：访问控制、物理媒体保护、路由选择控制
- 通过**加密**提供：对称加密、非对称加密
- 其他：数据填充、虚假事件、保护PDU头、时间可变域

### 5.6 完整性框架

**完整性违规操作**：未授权的数据修改/创建/删除/插入/重放

**完整性机制**：
- 阻止媒体访问：物理隔离、路由控制、访问控制
- 探测非授权修改：密封、数字签名、数据重复、数字指纹、消息序列号

### 5.7 抗抵赖框架

**四个阶段**：
1. **证据生成**：生成事件/行为的证据
2. **证据传输、存储及恢复**：实体间传输或存储
3. **证据验证**：验证证据的充分性
4. **解决纠纷**：仲裁者评估并确定

## 六、数据库安全设计 ⭐

### 6.1 评估标准

**TCSEC安全等级**（4大类7个等级）：

| 类别 | 等级 | 说明 |
|------|------|------|
| D | D | 基本无安全保护 |
| C | C1, C2 | 提供安全保护措施（非真正安全产品） |
| B | B1, B2, B3 | **强制存取控制**（真正安全产品） |
| A | A1 | 最高安全级别 |

> **安全产品 = B1级以上**；TDI是TCSEC在数据库方面的扩充解释。

### 6.2 数据库完整性设计 ⭐

**完整性约束6类**：

| 类别 | 静态 | 动态 |
|------|------|------|
| 列级 | Not Null、Unique Key、Check | — |
| 元组级 | Unique Key、Check | — |
| 关系级 | Primary Key、Referential | 存储过程 |

**设计原则**：
1. 静态约束尽量包含在数据库模式中，动态约束由应用程序实现
2. 实体完整性和引用完整性最重要，尽量应用
3. 慎用触发器（性能开销大、多级触发难控制），优先用Before型语句级
4. 需求分析阶段制定命名规范
5. 根据业务规则细致测试
6. 专职数据库设计小组全程负责
7. 采用CASE工具降低工作量

**设计阶段**：需求分析（确定业务规则）→ 概念结构设计（ERD）→ 逻辑结构设计（选择实现方式）

## 七、系统架构脆弱性分析 ⭐

### 7.1 脆弱性来源

| 来源 | 说明 |
|------|------|
| 软件设计瑕疵 | 协议设计缺陷、组件添加引入漏洞 |
| 软件实现弱点 | 实现方式引起漏洞（如缓冲区溢出） |
| 软件本身瑕疵 | 未做数据检查、资源耗尽处理不当、不正确使用系统调用 |
| 错误配置 | 默认配置、不正确部署 |

### 7.2 脆弱性生命周期

**四阶段**：引入 → 产生破坏效果 → 被修补 → 消失

### 7.3 典型架构脆弱性对比 ⭐⭐⭐

| 架构 | 主要脆弱性 |
|------|-----------|
| **分层架构** | ①层间脆弱性（底层错误→全系统崩溃）②层间通信性能下降 |
| **C/S架构** | ①客户端被分析/截取 ②网络开放性暴露 ③协议安全先天不足 |
| **B/S架构** | HTTP协议比C/S更易被病毒入侵 |
| **事件驱动** | ①组件控制力削弱 ②数据交换困难 ③逻辑关系复杂 ④易死循环 ⑤高并发问题 |
| **MVC架构** | ①复杂性增加 ②视图与控制器紧密连接 ③视图低效访问模型 ④缺少安全验证 |
| **微内核** | ①难以整体优化 ②进程间通信开销大 ③通信损失率高 |
| **微服务** | ①分布式系统复杂性 ②服务间通信机制 ③多服务管理复杂性 |

## 八、易混淆概念对比

### 1. BLP vs Biba（最核心对比）

| | BLP | Biba |
|--|-----|------|
| **保护目标** | 机密性 | 完整性 |
| **读规则** | 不上读（No Read Up） | 不下读（No Read Down） |
| **写规则** | 不下写（No Write Down） | 不上写（No Write Up） |
| **信息流** | 向上流 | 向下流 |
| **典型场景** | 军事保密 | 数据防篡改 |

### 2. CWM vs Biba

| | CWM | Biba |
|--|-----|------|
| 完整性方法 | 事务处理 + 职责分离 | 完整性级别分层 |
| 核心机制 | CDI/UDI + IVP + TP | 完整性级别规则 |
| 应用 | 银行系统 | 通用数据保护 |

### 3. DAC vs MAC vs RBAC

| | DAC | MAC | RBAC |
|--|-----|-----|------|
| 全称 | 自主访问控制 | 强制访问控制 | 基于角色的访问控制 |
| 控制方式 | 资源所有者决定 | 系统强制执行 | 通过角色分配权限 |
| 灵活性 | 高 | 低 | 中 |
| 安全性 | 较低 | 较高 | 适中 |

## 九、高频考点速记 ⭐

1. **BLP模型**：机密性 → 不上读、不下写（No Read Up, No Write Down）
2. **Biba模型**：完整性 → 不下读、不上写（No Read Down, No Write Up）
3. **CWM模型**：银行事务 → CDI/UDI + IVP + TP + 职责分离
4. **Chinese Wall**：利益冲突 → 公司数据集(CD) + 利益冲突组(COI)
5. **WPDRRC**：预警→保护→检测→响应→恢复→反击（中国提出）
6. **安全三要素**：人员（核心）、策略（桥梁）、技术（保证）
7. **OSI安全服务**：鉴别、访问控制、数据机密性、数据完整性、抗抵赖
8. **会话层**：OSI中唯一不适合配置安全服务的层
9. **TCSEC B1级**：安全产品的最低门槛
10. **数据库完整性**：静态约束→DBMS模式，动态约束→应用程序
