# 云架构（通俗 + 考点版）

## 一、核心定义

**云架构**，是**基于云计算基础设施**设计、部署、运行的软件 / 系统架构，不再局限于本地物理服务器，依托云平台的算力、存储、网络、中间件等云上资源，完成系统搭建、运维、弹性伸缩。

核心思想：**资源云上化、能力服务化、运维托管化**。

---

## 二、核心特征（必记）

1. **资源弹性伸缩**
    
    流量暴涨自动加机器，流量低谷自动缩容，按需付费，不用提前囤积硬件。
2. **服务化 / 组件化**
    
    大量复用云厂商现成服务（对象存储、数据库、MQ、缓存、CDN、AI 能力等），不用从零开发。
3. **分布式 + 高可用**
    
    多可用区、多节点部署，单节点故障不影响整体，云上天然支持容灾。
4. **按需租用、按量计费**
    
    区别传统自建机房，采用**租赁模式**，降低硬件与运维成本。
5. **自动化运维**
    
    结合容器、编排工具、监控告警、CI/CD，实现发布、扩容、故障自愈自动化。

---

## 三、按云服务层级划分（IaaS / PaaS / SaaS，最经典分类）

这是云架构最基础的三层，从上到下，**租户管控的范围越来越大**：

### 1. IaaS 基础设施即服务

- 厂商提供：**虚拟机、云服务器、云硬盘、虚拟网络、负载均衡** 等硬件层资源。
- 你负责：操作系统、中间件、应用、代码、运维全部自己管。
- 类比：租毛坯服务器。
- 例子：阿里云 ECS、腾讯云 CVM。

### 2. PaaS 平台即服务

- 厂商提供：**运行环境、数据库、缓存、消息队列、开发框架**等平台能力。
- 你负责：只写业务代码，不用管服务器、系统、底层运维。
- 类比：租精装修场地，直接摆家具营业。
- 例子：云数据库 RDS、Serverless 函数计算、应用引擎。

### 3. SaaS 软件即服务

- 厂商提供：**完整可直接使用的软件**，部署、运维、升级全由厂商负责。
- 你负责：仅使用功能，零部署、零维护。
- 类比：直接用现成 APP / 网页。
- 例子：在线办公软件、企业 CRM、网盘、在线会议系统。

> 补充：现在主流还有 **Serverless（无服务器架构）**，属于 PaaS 延伸，极致轻量化，只关注代码，连服务器实例都不用管理。

## 四、常见云架构风格 / 落地形态

结合你之前学的架构风格，云上主流实现：

1. **云原生架构**
    
    当下主流，基于 **容器 (Docker) + 容器编排 (K8s) + 微服务 + DevOps** 整套体系，专为云环境设计，弹性、迭代、扩缩容能力最强。
2. **分布式微服务云架构**
    
    把微服务部署在云主机 / 容器中，搭配云上网关、注册中心、链路追踪、监控，互联网业务最常用。
3. **事件驱动云架构**
    
    依托云上消息队列、事件总线，实现异步解耦，用于异步任务、数据流转。
4. **混合云架构**
    
    部分业务 / 数据跑在公有云，核心涉密系统留在本地机房，两者打通互通（政企、传统企业常用）。
5. **多云架构**
    
    同时使用多家云厂商服务，避免厂商绑定，提升容灾与议价能力。

## 五、适用场景 & 对比传统架构

### 适用场景

- 互联网业务、流量波动大的系统（电商、直播、APP、小程序）
- 创业 / 中小企业，不想自建机房、节约硬件和运维成本
- 业务快速迭代、需要敏捷发布的项目
- 需要异地容灾、高可用的业务

### 和传统本地架构核心区别

表格

|维度|传统机房架构|云架构|
|---|---|---|
|资源|固定硬件，扩容慢|弹性伸缩，秒级扩缩容|
|成本|一次性投入高，闲置浪费|按需付费，成本可控|
|运维|全自主运维，工作量大|底层运维由云厂商承接|
|部署|流程繁琐，上线慢|容器 + CI/CD，快速发布|
|容灾|自建容灾，成本高|云上多可用区，天然高可用|

---

## 六、一句话总结

**云架构 = 把系统跑在云端资源上，依托云的弹性、托管能力，结合微服务、容器、自动化运维打造的整套架构方案；分为 IaaS/PaaS/SaaS 三层，云原生是目前主流落地形态。**
