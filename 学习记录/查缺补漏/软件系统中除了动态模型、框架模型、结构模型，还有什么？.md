# 软件系统中除了动态模型、框架模型、结构模型，还有什么？

除了你提到的**结构模型、框架模型、动态模型**，软件体系结构里标准还有**过程模型、功能模型**；再加上工程与建模常用的**视图模型、数据模型、行为模型、部署模型**等。下面分两类说清楚：

## 一、软件体系结构五大核心模型（软考 / 教材标准）

1. **结构模型（Structural）**
   
    最基础，讲 “**构件 + 连接件**” 怎么拼，如模块、接口、依赖。
    
2. **框架模型（Framework）**
   
    偏 “**整体骨架**”，不抠细节，定大结构与主流程，如分层、微服务框架。
    
3. **动态模型（Dynamic）**
   
    讲 “**运行时行为**”：交互、状态变化、重构、演化，如时序、状态机。
    
4. **过程模型（Process）**
   
    讲 “**系统怎么造出来**”：开发步骤、生命周期、迭代 / 瀑布流程。
    
5. **功能模型（Functional）**
   
    讲 “**功能分层与服务**”：上层依赖下层，按能力划分，类似分层架构。
    

---

## 二、工程中常用的其他模型（UML / 架构视图）

### 1. 视图模型（4+1 视图）

- **逻辑视图**：功能与业务逻辑（类图、用例图）
- **开发视图（模块）**：代码模块与组织（包图、组件图）
- **进程视图**：运行时进程、线程、并发
- **物理视图（部署）**：硬件、网络、节点分布
- **+1 场景视图**：核心用例，串起所有视图

### 2. 数据模型（Data）

- 概念 / 逻辑 / 物理数据模型
- ER 图、数据流图 DFD、数据字典

### 3. 行为模型（Behavioral）

- 时序图、活动图、状态机图
- 事件驱动模型、交互模型

### 4. 部署模型（Deployment）

- 节点、容器、服务器、网络拓扑
- 微服务的集群、扩容、容灾部署

### 5. 其他常见

- **领域模型（DDD）**：限界上下文、聚合根
- **安全模型**：权限、认证、加密、风控
- **性能模型**：吞吐、延迟、资源占用
- **成本模型**：资源成本、运维成本

## 一、体系结构五大核心模型（教材 / 考试必考）

表格

| 模型名称 | 核心关注点                            | 常用图示 & 说明                   |
| ---- | -------------------------------- | --------------------------- |
| 结构模型 | 系统由哪些**组件 / 模块**组成、组件间静态依赖与连接关系  | 组件图、模块关系图；描述静态组织架构          |
| 框架模型 | 系统整体骨架、顶层架构风格与通用约束（分层、微服务、SOA 等） | 架构拓扑图；定义整体规范，不纠结细节实现        |
| 动态模型 | 系统**运行时**行为、交互、状态变化、流转逻辑         | 时序图、状态图、活动图；关注调用流程、状态切换     |
| 功能模型 | 系统具备的业务能力、功能划分、功能间调用关系           | 数据流图 DFD、功能分解图；按业务能力拆解系统    |
| 过程模型 | 软件**研发全流程**、生命周期、开发流程规范          | 流程图；瀑布、迭代、敏捷、DevOps 流程都属于此类 |

## 三、精简速记口诀

1. 核心五模型：**结、框、动、功、过**（结构、框架、动态、功能、过程）
2. 架构视图：**逻、开、进、物、场景**（4+1 视图）
3. 实战补充：**数据、领域、行为、安全、性能**

---

## 补充区分（易混点）

1. 动态模型 ≠ 行为模型：二者高度重合，**动态模型**偏架构运行流转，**行为模型**偏代码 / 组件层面的事件与动作；
2. 结构模型 ≠ 开发视图：结构模型是宏观架构组件，开发视图聚焦代码层级模块；
3. 部署模型归属物理视图，专门对应服务器、容器、网络等硬件 / 环境落地。
