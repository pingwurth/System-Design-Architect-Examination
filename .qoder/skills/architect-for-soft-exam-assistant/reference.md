# 参考文档

## 1. 扫描脚本详细说明

### scan_markdown.py 脚本功能
- **输入**：指定目录路径
- **输出**：/tmp/content.index 文件
- **格式**：TSV（制表符分隔）
- **列**：文件名、行号、类型、文本

### 支持的类型
- `H1` - 一级标题
- `H2` - 二级标题
- `H3` - 三级标题
- `H4` - 四级标题
- `H5` - 五级标题
- `BOLD` - 加粗文本

### 使用示例
```bash
# 基本用法
python scripts/scan_markdown.py /path/to/chapters

# 指定输出文件
python scripts/scan_markdown.py /path/to/chapters -o /tmp/custom.index

# 详细模式
python scripts/scan_markdown.py /path/to/chapters -v
```

## 3. 常见考点分类详解

### 3.1 架构风格
- **分层架构**：将系统分为多个层次，每层提供特定服务
- **微服务架构**：将应用拆分为小型、独立的服务
- **SOA架构**：面向服务的架构，强调服务的重用和组合
- **事件驱动架构**：基于事件的异步通信模式
- **管道-过滤器架构**：数据流通过一系列处理组件

### 3.2 质量属性
- **性能**：系统响应时间和吞吐量
- **可用性**：系统正常运行时间的比例
- **安全性**：保护系统免受威胁的能力
- **可修改性**：系统易于修改和扩展的程度
- **可靠性**：系统在规定条件下完成功能的能力

### 3.3 设计模式
- **创建型模式**：工厂方法、抽象工厂、单例、建造者、原型
- **结构型模式**：适配器、桥接、组合、装饰、外观、享元、代理
- **行为型模式**：责任链、命令、解释器、迭代器、中介者、备忘录、观察者、状态、策略、模板方法、访问者

### 3.4 架构评估方法
- **ATAM**（架构权衡分析法）：评估架构对质量属性的满足程度
- **SAAM**（软件架构分析法）：评估架构的可修改性
- **CBAM**（成本效益分析法）：评估架构决策的经济效益

## 4. 答案质量标准

### 4.1 准确性要求
- 答案必须基于教材内容或可靠的知识体系
- 引用具体章节和行号（如有）
- 避免模糊或不确定的表述

### 4.2 完整性要求
- 覆盖题目的所有要求
- 提供必要的背景信息
- 包含相关的扩展知识点

### 4.3 清晰性要求
- 使用专业术语，但保持易懂
- 结构清晰，逻辑连贯
- 提供具体的例子和说明

## 5. 扫描结果分析技巧

### 5.1 关键词匹配策略
1. **精确匹配**：查找完全相同的关键词
2. **模糊匹配**：查找包含关键词的文本
3. **同义词匹配**：查找相关概念的同义词
4. **上下文匹配**：结合上下文理解关键词含义

### 5.2 结果过滤方法
1. **按类型过滤**：只查看标题或加粗文本
2. **按章节过滤**：只查看特定章节的内容
3. **按相关性排序**：优先查看最相关的结果

### 5.3 知识点定位
1. **标题定位**：通过标题快速找到相关章节
2. **加粗文本定位**：通过加粗文本找到重点内容
3. **行号定位**：通过行号精确找到具体内容

2. 确认文件存在且可读
3. 检查文件编码（UTF-8）

### 6.3 知识点缺失处理
1. 扩大搜索范围，查找相关章节
2. 使用同义词或相关概念搜索
3. 基于已有知识进行推理和分析

## 10. 常见问题解答

### Q1: 扫描脚本运行失败怎么办？
A: 检查 Python 环境、文件路径和权限，尝试手动运行脚本查看错误信息。

### Q2: 找不到相关知识点怎么办？
A: 扩大搜索范围，使用同义词搜索，或基于已有知识进行推理分析。

### Q3: 答案不准确怎么办？
A: 验证教材内容，检查引用出处，必要时提供多个可能的答案。

### Q4: 如何提高检索效率？
A: 定期更新扫描结果，使用缓存机制，优化关键词匹配策略。

### Q5: 如何处理复杂的案例分析题？
A: 分步骤分析，综合多个知识点，提供详细的解决方案和关键要点。
