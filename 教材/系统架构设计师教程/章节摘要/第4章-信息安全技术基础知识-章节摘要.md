### 4.1 信息安全基础知识

#### 信息安全5个基本要素（⭐）

| 要素 | 含义 |
|------|------|
| 机密性 | 确保信息不被未授权访问、泄露 |

| 可控性 | 确保信息传播和使用在可控范围内 |
| 可审查性 | 确保信息安全事件可追溯、可追责 |

#### 安全范围4个方面（⭐）

| 方面 | 核心属性 |
|------|---------|
| 设备安全 | 稳定性、可靠性、可用性 |
| 数据安全 | 秘密性、完整性、可用性 |
| 内容安全 | 政治健康、法律合规、道德规范 |
| 行为安全 | 秘密性、完整性、可控性 |

#### 信息存储安全

- **信息使用安全**：用户标识验证、存取权限限制
- **系统安全监控**：实时监测系统运行状态
- **计算机病毒防治**：预防、检测、清除

#### 访问控制两种方法

| 方法 | 说明 |
|------|------|
| 隔离控制法 | 物理隔离、时间隔离、逻辑隔离、密码隔离 |
| 限制权限法 | 通过权限设置限制用户对资源的访问 |

#### 网络安全漏洞4类

1. **物理安全**漏洞
2. **软件安全**漏洞
3. **不兼容使用**安全漏洞
4. **安全哲理**选择不当

#### 网络安全威胁5类（⭐）

| 威胁类型 | 说明 |
|---------|------|
| 非授权访问 | 未经授权访问系统资源 |
| 信息泄露或丢失 | 敏感信息被窃取或丢失 |
| 破坏数据完整性 | 篡改、删除或破坏数据 |
| 拒绝服务攻击 | 使系统无法正常提供服务 |
| 利用网络传播病毒 | 通过网络传播恶意代码 |

#### 安全措施目标5个

1. **访问控制** — 限制未授权访问
2. **认证** — 确认身份真实性
3. **完整性** — 保证数据不被篡改
4. **审计（不可抵赖性）** — 行为可追溯

### 4.4 信息加解密技术（⭐高频考点区）

#### 密码学基础

- **密码学** = 密码编码学 + 密码分析学
- **保密通信模型**：
  - 加密：`C = E(K, P)` （密文 = 加密函数(密钥, 明文)）
  - 解密：`P = D(K, C)` （明文 = 解密函数(密钥, 密文)）

#### 对称密钥加密（⭐）

> 特点：加密和解密使用**相同**的密钥

| 算法 | 密钥长度 | 分组大小 | 特点 |
|------|---------|---------|------|
| DES | 56位 | 64位明文块 | 16次变换，安全性较低 |
| 三重DES | 112位（2个密钥） | 64位 | 3次加密，安全性提高 |
| IDEA | 128位 | 64位 | 8轮迭代，比DES快 |
| AES（⭐） | 128/192/256位 | 128位 | Rijndael算法，免版税，当前标准 |

**三重DES加密过程**：
```
C = E(K1, D(K2, E(K1, P)))
```
- 用密钥K1加密 → 用密钥K2解密 → 再用K1加密
- 有效密钥长度：112位

#### 非对称密钥加密（⭐）

> 特点：加密和解密使用**不同**的密钥（公钥 + 私钥）

| 用途 | 加密方式 | 解密方式 |
|------|---------|---------|
| 保密通信 | 公钥加密 | 私钥解密 |
| 数字签名 | 私钥加密 | 公钥解密（验证） |

**RSA算法**（⭐）：
- **数学基础**：基于大素数分解的困难性
- **算法步骤**：
  1. 选择两个大素数 `p` 和 `q`
  2. 计算 `n = p × q`
  3. 计算 `z = (p-1)(q-1)`（欧拉函数）
  4. 选择整数 `e`，使得 `1 < e < z` 且 `gcd(e, z) = 1`
  5. 计算 `d`，使得 `d × e ≡ 1 (mod z)`
  6. 公钥 `(n, e)`，私钥 `(n, d)`

**RSA计算示例**：
```
取 p=3, q=11
n = p×q = 33
z = (p-1)(q-1) = 2×10 = 20
选 e=7（与20互素）
求 d：d×7 ≡ 1 (mod 20)，d=3

加密：C = P^e mod n = P^7 mod 33
解密：P = C^d mod n = C^3 mod 33
```

### 4.5 密钥管理技术

#### 对称密钥分配（⭐）

**密钥使用控制**：
- 密钥标签
- 控制矢量

**4种分配方式**：

| 方式 | 说明 | 安全性 |
|------|------|--------|
| A物理发送给B | 人工传递密钥 | 安全但效率低 |
| 第三方物理发送 | 可信第三方传递 | 较安全 |
| 已有密钥加密新密钥 | 用旧密钥保护新密钥 | 密钥链风险 |
| KDC分配（⭐） | 密钥分配中心自动分配 | 最常用方案 |

**KDC分层结构**：
```
全局KDC（Global KDC）
    ├── 本地KDC-1（Local KDC）
    │       ├── 用户A
    │       └── 用户B
    └── 本地KDC-2（Local KDC）
            ├── 用户C
            └── 用户D
```

> **重要公式**（⭐）：N个用户通信需要 **N(N-1)/2** 个会话密钥，但只需 **N** 个主密钥

#### 公钥管理4种方式（⭐）

| 方式 | 优点 | 缺点 |
|------|------|------|
| 公开发布 | 简单方便 | 易被伪造，无法验证真实性 |
| 公用目录表 | 可信实体维护 | 管理员密钥被盗则全线失守 |
| 公钥管理机构 | 更严密的安全控制 | 机构成为系统瓶颈 |
| 公钥证书CA（⭐） | 标准化、可扩展、最安全 | 需要PKI基础设施支持 |

**公钥证书格式**（⭐）：
```
CA = E_SKCA[T, IDA, PKA]
```
- `SKCA`：CA的私钥
- `T`：时间戳
- `IDA`：用户A的身份
- `PKA`：用户A的公钥

#### 公钥加密分配单钥密钥（5步协议）

1. A向CA请求B的公钥
2. CA返回B的公钥证书
3. A用B的公钥加密会话密钥，发送给B
4. B用私钥解密获得会话密钥
5. A、B使用会话密钥进行保密通信

### 4.6 访问控制及数字签名技术

#### 访问控制3要素（⭐）

| 要素 | 符号 | 说明 |
|------|------|------|
| 主体 | S | 发起访问的实体（用户、进程） |
| 客体 | O | 被访问的资源（文件、数据库） |
| 控制策略 | KS | 访问规则集合 |

#### 访问控制实现3方面

1. **认证** — 验证主体身份
2. **控制策略实现** — 执行访问规则
3. **审计** — 记录和检查访问行为

#### 访问控制4种实现技术（⭐）

| 技术 | 存储方式 | 优点 | 缺点 |
|------|---------|------|------|
| 访问控制矩阵 | 二维矩阵 | 理论完整 | 实际太大，存储浪费 |
| 访问控制表ACL（⭐） | 按列保存（客体角度） | 最流行，方便查客体权限 | 查主体权限需遍历 |
| 能力表 | 按行保存（主体角度） | 方便查主体权限 | 权限传递困难 |
| 授权关系表 | 按非空元素保存 | 安全数据库常用 | 查询效率较低 |

#### 数字签名（⭐）

**数字签名5个条件**：

| 条件 | 含义 |
|------|------|
| 可信 | 签名者身份可被验证 |
| 不可伪造 | 其他人无法仿造签名 |
| 不可重用 | 签名不能被用于其他文件 |
| 文件不可改变 | 签名后文件内容不能被篡改 |
| 不可抵赖 | 签名者不能否认自己的签名 |

**两种签名方式对比**：

| 方式 | 过程 | 特点 |
|------|------|------|
| 对称密钥签名 | 需要仲裁人BB作为中间人 | 依赖可信第三方 |
| 公钥签名（⭐） | 私钥签名 DA(P)，公钥验证 EA 解密 | 无需第三方，更实用 |

**实践优化**：
- 对整个文件签名效率低
- 实际做法：对文件的 **Hash值** 签名（⭐）
- 只需签名固定长度的摘要，大幅提高效率

### 4.7 抗攻击技术

#### 密钥选择3要素

1. **增大密钥空间** — 密钥越长，暴力破解越困难
2. **选择强钥** — 避免弱密钥（如全0、全1）
3. **密钥随机性** — 密钥应具有良好的随机性

#### 密钥分类

| 类型 | 用途 |
|------|------|
| 数据加密密钥 DK | 直接用于加密数据 |
| 密钥加密密钥 KK | 用于保护其他密钥 |

#### DoS攻击（⭐）

**两种基本思路**：
1. 使缓冲区满，不接收新请求
2. IP欺骗，迫使连接复位

**4种攻击模式**：

| 模式 | 说明 |
|------|------|
| 消耗资源 | 耗尽带宽、CPU、内存等 |
| 破坏配置 | 篡改系统配置使其不可用 |
| 物理破坏 | 破坏硬件设备 |
| 利用处理错误 | 触发程序异常导致崩溃 |

**DDoS三级结构**（⭐）：
```
Client（客户端/攻击者）
    ↓ 发出攻击指令
Handler（主控端）
    ↓ 转发并放大攻击
Agent（代理端/僵尸主机）
    ↓ 向目标发送攻击流量
Target（目标系统）
```

**DoS防御方法**：
- 数据包特征识别
- 防火墙监视与过滤
- 通信量统计分析
- 修正已知系统漏洞

#### 欺骗攻击（⭐）

| 类型 | 原理 | 危害 |
|------|------|------|
| ARP欺骗 | 伪造ARP应答，更新目标缓存表 | 中间人攻击、流量劫持 |
| DNS欺骗 | 冒充域名服务器，返回虚假IP | 钓鱼网站、流量劫持 |
| IP欺骗 | 利用TCP三次握手漏洞，伪造源IP | 绕过IP认证、会话劫持 |

#### 端口扫描技术

| 扫描方式 | 特点 |
|---------|------|
| 全TCP连接扫描 | 完成三次握手，最准确但易被检测 |
| 半打开式SYN扫描 | 只发SYN，不完全连接，较隐蔽 |
| FIN扫描（秘密扫描） | 发送FIN包，最隐蔽 |
| 第三方扫描 | 利用第三方主机进行扫描 |

#### TCP/IP堆栈攻击

- **SYN Flooding**：大量SYN请求耗尽连接资源
- **ICMP攻击**：利用ICMP协议进行攻击（如Ping of Death）
- **SNMP攻击**：利用SNMP协议漏洞获取网络信息

#### 系统漏洞扫描（⭐）

| 类型 | 优点 | 缺点 |
|------|------|------|
| 基于网络 | 价格便宜、不需管理员介入、不需安装、维护简便 | 无法深入系统内部 |
| 基于主机 | 漏洞数量多、集中化管理、网络流量负载小 | 需要在每台主机安装 |

### 4.8 安全保障体系与评估

#### 安全保护等级（⭐）

| 等级 | 名称 | TCSEC对应 | 特点 |
|------|------|-----------|------|
| 第1级 | 用户自主保护级 | C1 | 基本安全，自主访问控制 |
| 第2级 | 系统审计保护级 | C2 | 审计追踪，更细粒度控制 |
| 第3级 | 安全标记保护级 | B1 | 强制访问控制，安全标记 |
| 第4级 | 结构化保护级 | B2 | 形式化安全策略模型 |
| 第5级 | 访问验证保护级 | B3 | 最高级，形式化验证 |

#### 安全风险管理（⭐）

**风险评估基本要素**：
```
脆弱性 ←→ 资产 ←→ 威胁
   ↓          ↓        ↓
  风险 ← 安全措施 ← 安全事件
```

**相关属性**：
- 业务战略
- 资产价值
- 安全需求
- 安全事件
- 残余风险（采取措施后剩余的风险）

**评估形式**：

| 形式 | 说明 |
|------|------|
| 自评估 | 组织内部自行评估 |
| 他评估 | 委托第三方专业机构评估 |

**风险计算5步**：
```
1. 资产识别与赋值
   ↓
2. 威胁分析与赋值
   ↓
3. 脆弱性识别与赋值
   ↓
4. 计算安全事件发生的可能性
   ↓
5. 计算风险值
```

**脆弱性评估方法**：
- 问卷调查
- 人员问询
- 工具扫描
- 手动检查
- 文档审查
- 渗透测试

| 集中管理 | 支持 | 支持 |

## 高频考点速记

### ⭐ 必背清单

1. **信息安全5要素**：机密性、完整性、可用性、可控性、可审查性

2. **安全框架核心原则**："三分技术，七分管理"
   - 技术体系 + 组织机构体系 + 管理体系

3. **对称加密算法参数**：
   - DES：56位密钥，64位分组，16次变换
   - IDEA：128位密钥，64位分组，8轮迭代
   - AES：128/192/256位密钥，Rijndael算法，免版税

4. **RSA算法核心**：
   - 基于大素数分解困难性
   - `n = p × q`，`z = (p-1)(q-1)`
   - 公钥加密 + 私钥解密 = 保密通信
   - 私钥加密 + 公钥解密 = 数字签名

5. **公钥证书CA**：
   - 最优公钥管理方案
   - `CA = E_SKCA[T, IDA, PKA]`

6. **访问控制表ACL vs 能力表**：
   - ACL按列（客体）保存 → 查客体权限方便
   - 能力表按行（主体）保存 → 查主体权限方便

7. **数字签名5条件**：可信、不可伪造、不可重用、文件不可改变、不可抵赖

8. **DDoS三级结构**：Client（客户端）→ Handler（主控端）→ Agent（代理端）

9. **安全保护5等级**：
   - C1用户自主 → C2系统审计 → B1安全标记 → B2结构化保护 → B3访问验证

10. **风险评估要素关系**：
    - 脆弱性 + 资产 + 威胁 → 风险
    - 风险计算：资产识别→威胁分析→脆弱性识别→可能性计算→风险值计算

### ⚠️ 易错点提醒

| 易错点 | 正确理解 |
|--------|---------|
| 三重DES密钥长度 | 有效密钥112位（2个56位密钥），不是168位 |
| RSA安全性基础 | 大素数**分解**困难，不是离散对数 |
| 数字签名加密方向 | **私钥**签名，**公钥**验证（与保密通信相反） |
| 会话密钥数量 | N(N-1)/2 个会话密钥，但只需N个主密钥 |
| ACL存储方向 | 按**列**（客体角度）保存，不是按行 |
