# 第11章 未来信息综合技术 - 复习笔记

> **考试大纲映射**：10. 未来信息综合技术 — CPS、AI、机器人、边缘计算、数字孪生、云计算、大数据

## 章节概述

本章涵盖近年来新兴的信息技术概念，涉及七大技术领域：信息物理系统（CPS）、人工智能（AI）、机器人、边缘计算、数字孪生、云计算和大数据。这些技术是计算机信息技术的延伸，具有高度综合性和跨学科特征。

## 一、信息物理系统（CPS）⭐⭐⭐

### 1.1 概念与本质

| 要素 | 内容 |
|------|------|
| 术语来源 | 1992年 NASA 首次提出；2006年 Helen Gill 详细描述 |
| 本质 | 构建信息空间与物理空间之间基于**数据自动流动**的闭环赋能体系 |
| 核心闭环 | **状态感知 → 实时分析 → 科学决策 → 精准执行** |
| 目标 | 解决复杂性和不确定性问题，实现资源优化配置 |
| 数据形态变化 | 隐性数据 → 显性数据 → 信息 → 知识 |

### 1.2 三级体系架构 ⭐

| 层级 | 特征 | 重点建设 |
|------|------|----------|
| **单元级** | CPS最小单元，不可分割；具备可感知、可计算、可交互、可延展、自决策功能 | 感控设备安装、工艺数字化 |
| **系统级** | 多个单元级通过工业网络互联；实现自组织、自配置、自决策、自优化 | **工业网络建设**为重点 |
| **SoS级** | 多个系统级有机组合；实现数据汇聚、资产优化、运营优化 | **大数据平台、智能服务平台**为重点 |

> **关键功能对比**：系统级新增互联互通、即插即用、边缘网关、数据互操作、协同控制、监视诊断；SoS级新增数据存储/融合、分布式计算、大数据分析、数据服务。

### 1.3 技术体系 — "新四基" ⭐

| 要素 | 名称 | 作用 |
|------|------|------|
| **一硬** | 感知和自动控制 | 硬件支撑（传感器技术、虚实融合控制） |
| **一软** | 工业软件 | CPS的**核心**，固化计算和数据流程规则 |
| **一网** | 工业网络 | 互联互通和数据传输的网络载体 |
| **一平台** | 工业云和智能服务平台 | 数据汇聚、资源管控和能力服务 |

### 1.4 虚实融合控制四层 ⭐

| 层次 | 说明 |
|------|------|
| 嵌入控制 | 针对**物理实体**进行控制 |
| 虚体控制 | 在信息空间进行控制计算，针对**信息虚体** |
| 集控控制 | 通过**CPS总线**方式进行信息虚体的集成和控制 |
| 目标控制 | 通过即时比对判断生产是否达成目标 |

### 1.5 应用场景

- **智能设计**：产品/工艺仿真、生产线/工厂设计仿真
- **智能生产**：设备管理、生产管理、柔性制造
- **智能服务**：健康管理、智能维护、远程征兆性诊断、协同优化、共享服务
- **智能应用**：无人装备、产业链互动、价值链共赢

### 1.6 建设路径

**CPS体系设计 → 单元级CPS建设 → 系统级CPS建设 → SoS级CPS建设**（循序渐进、逐渐深入）

## 二、人工智能（AI）⭐⭐⭐

### 2.1 基本概念

| 分类 | 特征 |
|------|------|
| **弱人工智能** | 不能真正推理和解决问题，实现特定功能的专用智能；当前主流 |
| **强人工智能** | 真正能思维、有知觉和自我意识；分为**类人**与**非类人**；至少几十年内难以实现 |

### 2.2 发展历程关键事件 ⭐

| 时间 | 事件 |
|------|------|
| 1950 | 图灵提出**图灵测试** |
| 1956 | 达特茅斯会议，**"人工智能"术语诞生** |
| 1959 | Samuel 提出**机器学习** |
| 1968 | Feigenbaum 提出首个专家系统 **DENDRAL** |
| 1970s | 第一次AI寒冬（计算能力不足） |
| 1980 | Berliner 计算机战胜双陆棋世界冠军（第二次浪潮） |
| 1987 | LISP机市场崩塌，AI再次萧瑟 |
| 1997 | IBM **深蓝**战胜国际象棋冠军卡斯帕罗夫 |
| 2006 | Hinton 推动**深度学习** |
| 2011 | IBM **Watson** 问答系统 |
| 2012 | **Google Brain** 无监督学习识别猫 |
| 2016 | **AlphaGo** 击败围棋世界冠军李世石 |

### 2.3 关键技术

| 技术 | 要点 |
|------|------|
| **NLP** | 机器翻译、语义理解、问答系统 |
| **计算机视觉** | 图像提取/处理/理解；端到端AI算法 |
| **知识图谱** | 结构化语义知识库，节点+边的图数据结构；反欺诈、搜索、精准营销 |
| **人机交互** | 语音/情感/体感/脑机交互 |
| **VR/AR** | 数字化环境模拟，沉浸式体验 |

### 2.4 机器学习分类 ⭐⭐

#### 按学习模式分类

| 类型 | 训练数据 | 典型算法/应用 |
|------|----------|---------------|
| **监督学习** | 已标记样本集 | 回归、分类；垃圾邮件侦测 |
| **无监督学习** | 无标记样本集 | Apriori、KMeans、随机森林、PCA |
| **半监督学习** | 少量标注 + 大量未标识 | 图论推理、拉普拉斯SVM |
| **强化学习** | 反馈机制（奖赏） | Q-Learning、时间差学习；机器人控制 |

#### 按学习方法分类

| 类型 | 特征 |
|------|------|
| **传统机器学习** | 需手动特征提取，需领域专业知识；逻辑回归、SVM、KNN、决策树等 |
| **深度学习** | 无需人工特征提取，需大量数据和GPU算力；CNN、RNN |

#### 其他重要学习方式

| 类型 | 要点 |
|------|------|
| **迁移学习** | 利用已有模型参数指导新模型训练，减少数据量 |
| **主动学习** | 选择性查询最有用的未标记样本，由专家标记 |
| **演化学习** | 基于演化算法，维护解的集合，启发式产生新解 |

### 2.5 机器学习面临的挑战

- **黑箱问题**：需要可解释性、可干预性
- **计算成本高**：需要轻量级算法
- **追求简单美**的规律

## 三、机器人技术 ⭐⭐

### 3.1 概念与发展

| 要素 | 内容 |
|------|------|
| Robot 来源 | 1920年捷克作家卡佩克剧本，捷克语"苦力/奴隶" |
| 定义不统一 | 因机器人仍在发展，涉及哲学问题 |

### 3.2 三代机器人 ⭐

| 代次 | 名称 | 特征 | 时间 |
|------|------|------|------|
| 第一代 | **示教再现型** | 通过示教存储程序，重复动作；PUMA（1962） | 1947- |
| 第二代 | **感觉型** | 具有力觉、触觉、视觉等感知能力 | 1970s- |
| 第三代 | **智能型** | 多种传感器，复杂逻辑推理、自主决策 | 1990s- |

### 3.3 机器人4.0 核心技术 ⭐⭐

| 核心技术 | 要点 |
|----------|------|
| **云-边-端无缝协同计算** | 云侧=高性能计算+知识存储；边缘侧=数据处理+协同共享；端侧=实时操作；需动态任务迁移机制 |
| **持续学习与协同学习** | 少量数据建立识别→自主找数据→自动标注→重新训练；机器人间数据共享 |
| **知识图谱** | 需动态/个性化知识；需与感知决策能力结合；分布于云/边/端 |
| **场景自适应** | 三维语义理解+预测事件→改变行为模式；关键是**场景预测**能力 |
| **数据安全** | 端到端安全传输+服务器端安全存储；机器人侧/云侧/边缘侧需求不同 |

### 3.4 机器人分类

| 分类方式 | 类型 |
|----------|------|
| 按控制方式 | 操作、程序、示教再现、智能、综合 |
| 按应用行业 | 工业机器人、服务机器人、特殊领域机器人 |

## 四、边缘计算 ⭐⭐⭐

### 4.1 核心概念

| 要素 | 内容 |
|------|------|
| 类比 | **章鱼**：60%神经元分布在腕足，40%在脑部 |
| 本质 | 将数据处理、应用运行由网络中心**下放到网络边缘节点** |
| 核心优势 | 就近处理数据，减少传输延迟，降低云端压力 |

### 4.2 多种定义 ⭐

| 组织 | 定义要点 |
|------|----------|
| **ECC** | 云计算在数据中心之外的延伸和演进；三类形态：云边缘、边缘云、云化网关 |
| **OpenStack** | 在靠近数据输入或用户的地方提供计算、存储和网络带宽 |
| **ISO/IEC** | 将主要处理和数据存储放在网络边缘节点的分布式计算形式 |
| **ETSI** | 靠近移动用户，减少时延，提高用户体验 |

### 4.3 三类落地形态 ⭐

| 形态 | 说明 | 示例 |
|------|------|------|
| **云边缘** | 云服务在边缘侧的延伸，逻辑上仍是云服务 | 华为IEF、阿里Link Edge、AWS Greengrass |
| **边缘云** | 在边缘侧构建中小规模云服务 | MEC、CDN、华为IEC |
| **云化网关** | 以云化技术重构嵌入式网关 | 协议转换、边缘计算 |

### 4.4 四大特点

| 特点 | 说明 |
|------|------|
| **联接性** | 基础；TSN、SDN、NFV、5G等 |
| **数据第一入口** | 大量、实时、完整的数据 |
| **约束性** | 防电磁、防尘、防爆、抗振动等 |
| **分布性** | 分布式计算/存储/智能/安全 |

### 4.5 边云协同 — 六种协同 ⭐⭐

| 协同类型 | 边缘侧 | 云端 |
|----------|--------|------|
| **资源协同** | 本地资源调度管理 | 资源调度管理策略 |
| **数据协同** | 数据采集、初步处理分析 | 海量数据存储、分析与价值挖掘 |
| **智能协同** | 按AI模型执行推理（分布式智能） | AI集中式模型训练，下发模型 |
| **应用管理协同** | 应用部署与运行环境 | 应用开发、测试环境 |
| **业务管理协同** | 模块化/微服务化应用实例 | 业务编排能力 |
| **服务协同** | 部分ECSaaS服务 | SaaS服务分布策略 |

> **关系**：边缘计算与云计算是**互补协同**关系，不是替代关系。

### 4.6 边缘计算安全 — CROSS

**C**onnectivity + **R**ealtime + data **O**ptimization + **S**mart + **S**ecurity

### 4.7 应用场景

| 场景 | 关键需求 |
|------|----------|
| **智慧园区** | 海量设备连接、实时数据处理、本地业务自治 |
| **安卓云/云游戏** | 安卓全栈云化、视频渲染、低时延 |
| **视频监控** | 边缘图像识别、智能存储、边云协同 |
| **工业物联网** | OPC UA over TSN、vPLC、质量检测 |
| **Cloud VR** | 渲染计算卸载到边缘；带宽降低30%，时延降低50% |

## 五、数字孪生体 ⭐⭐⭐

### 5.1 发展历程

| 阶段 | 时间 | 内容 |
|------|------|------|
| 技术准备期 | 1960-21世纪初 | CAD/CAE建模仿真、传统系统工程 |
| 概念产生期 | 2002-2010 | Grieves 2002提出概念模型；2009 AFRL首次命名"Digital Twin" |
| 领先应用期 | 2010-2020 | NASA、美军、GE等领先应用；ISO/IEC/IEEE标准化 |
| 深度扩展期 | 2020-2030 | 从智能制造向智慧城市、数字政府拓展 |

### 5.2 定义

> 数字孪生体是现有或将有的物理实体对象的数字模型，通过实测、仿真和数据分析来**实时感知、诊断、预测**物理实体对象的状态，通过优化和指令来**调控**物理实体对象的行为，通过数字模型间的相互学习来**进化**自身。

### 5.3 三种类型 ⭐

| 类型 | 说明 |
|------|------|
| **数字孪生原型体** (DTP) | 原型/模板 |
| **数字孪生实例体** (DTI) | 具体实例 |
| **数字孪生聚合体** (DTA) | 多个孪生体的聚合 |

### 5.4 核心技术体系 ⭐⭐

| 层次 | 技术 |
|------|------|
| **三项核心技术** | 建模、仿真、数字线程（数据融合） |
| **顶层框架技术** | 系统工程、MBSE（模型驱动系统工程） |
| **底层伴生技术** | 物联网 |
| **外围使能技术** | 云计算、机器学习、大数据、区块链 |
| **增强现实技术** | VR、AR、MR |

### 5.5 建模与仿真的关系

| | 建模 | 仿真 |
|--|------|------|
| 目的 | 将物理世界理解进行**简化和模型化** | **验证和确认**理解的正确性和有效性 |
| 地位 | 创建数字孪生体的**源头**和核心技术 | 保证数字孪生体与物理实体**有效闭环**的核心技术 |

### 5.6 应用领域

| 领域 | 要点 |
|------|------|
| **制造** | 产品设计仿真、数字生产线、多生产线"共智" |
| **产业** | 全产业链数字孪生；数化→互动→先知→先觉→共智 |
| **城市** | 数字孪生城市；传感监控即时性、信息集成性、决策科学性 |
| **战场** | 单体装备（数字孪生制造）+ 战场综合应用（体系级） |

## 六、云计算 ⭐⭐⭐

### 6.1 基本概念

| 要素 | 内容 |
|------|------|
| 提出时间 | 2007年10月，Google和IBM联合定义 |
| 内涵两方面 | **平台**（基础设施）和**应用**（云应用） |
| 虚拟化起源 | 1959年 Strachey 提出时间共享 |

### 6.2 三种服务模式 ⭐⭐

| 服务 | 说明 | 灵活性 | 方便性 |
|------|------|--------|--------|
| **SaaS** | 应用软件统一部署，按需订购 | 最低 | **最高** |
| **PaaS** | 分布式开发环境与平台 | 中等 | 中等 |
| **IaaS** | 虚拟化基础设施（CPU/存储/网络） | **最高** | 最低 |

> **PaaS是最关键的一层**，起支撑作用；相当于系统软件地位，为上层SaaS提供API。

### 6.3 四种部署模式 ⭐

| 模式 | 说明 |
|------|------|
| **公有云** | 向公众开放，价格低廉 |
| **社区云** | 特定社区组织专有 |
| **私有云** | 单个组织专用 |
| **混合云** | 公有云+私有云+社区云的组合 |

### 6.4 发展历程三条线

| 技术线 | 对应服务模式 |
|--------|-------------|
| 虚拟化技术 | IaaS |
| 分布式计算技术 | PaaS |
| 软件应用模式 | SaaS（起源于1999年，2003年Salesforce成功） |

## 七、大数据 ⭐⭐⭐

### 7.1 大数据定义 — 4V特征 ⭐⭐

| V | 含义 | 说明 |
|---|------|------|
| **Volume** | 大规模 | TB/PB级数据 |
| **Velocity** | 高速度 | 数据移动和处理速度要快 |
| **Variety** | 多样化 | 结构化+半结构化+非结构化 |
| **Value** | 价值 | 大数据潜藏的价值 |

> **SAS扩展**：在3V基础上增加**可变性**（Variability）和**复杂性**（Complexity）。

### 7.2 大数据五大挑战

| 挑战 | 内容 |
|------|------|
| 异构性 | 多格式数据需不同处理方法 |
| 规模 | 数据量不断增长 |
| 时间性 | 数据处理速度要求 |
| 复杂性 | 数据来源多样性、关联关系 |
| 隐私性 | 数据安全与隐私保护 |

### 7.3 大数据分析五阶段 ⭐

| 阶段 | 关键问题 |
|------|----------|
| **数据获取/记录** | 数据压缩、在线分析、元数据获取、数据来源追踪 |
| **信息抽取/清洗** | 复杂结构数据抽取；**大数据中广泛存在虚假数据** |
| **数据集成/聚集/表示** | 异构数据整合、语义统一描述 |
| **查询处理/建模/分析** | 噪声多、动态性、异构性；频繁模式分析 |
| **解释** | 数据出处（data provenance）、可视化、交互式探索 |

> **data provenance（数据出处）**：支持用户了解、验证、追踪分析结果的关键技术。

### 7.4 应用领域

| 领域 | 要点 |
|------|------|
| **制造业** | 从信息化→智慧化；传感器数据自我调节；预测性维护 |
| **服务业** | 个性化广告推送；零售行为建模；金融欺诈检测 |
| **交通** | 多源数据融合，最佳出行方式和路线 |
| **医疗** | 电子病历标准化；多维度数据仓库；决策支持系统 |

## 易混淆点对比

### 对比1：CPS vs 数字孪生 vs 物联网

| 维度 | CPS | 数字孪生 | 物联网 |
|------|-----|----------|--------|
| 核心 | 信息-物理闭环控制 | 物理实体的数字镜像 | 物物互联 |
| 强调 | 数据自动流动+控制 | 建模+仿真+数据融合 | 连接+感知 |
| 关系 | 数字孪生是CPS核心技术之一 | 物联网是底层伴生技术 | CPS的基础设施 |

### 对比2：边缘计算 vs 云计算 vs 雾计算

| 维度 | 云计算 | 边缘计算 | 雾计算 |
|------|--------|----------|--------|
| 位置 | 远端数据中心 | 网络边缘节点 | 介于云和端之间 |
| 数据特点 | 全局、非实时、长周期 | 局部、实时、短周期 | 中等 |
| 延迟 | 高 | **低** | 中 |
| 关系 | **互补协同**，非替代 | **互补协同**，非替代 | 补充 |

### 对比3：弱AI vs 强AI

| 维度 | 弱AI | 强AI |
|------|------|------|
