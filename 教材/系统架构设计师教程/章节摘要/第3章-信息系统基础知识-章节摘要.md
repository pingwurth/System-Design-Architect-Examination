## 核心知识点

### 3.1 信息系统概述

#### 定义

信息系统是一个**人机一体化系统**，具备以下 5 个基本功能：

| 序号 | 功能 | 说明 |
|:---:|------|------|
| 1 | **输入** | 采集原始数据 |
| 2 | **存储** | 保存数据和信息 |
| 3 | **处理** | 对数据进行加工转换 |
| 4 | **输出** | 将处理结果传递给用户 |
| 5 | **控制** | 对系统运行进行监控和调节 |

#### ⭐ 诺兰模型（Nolan Stage Model）— 高频考点

信息系统发展的 **6 个阶段**：

```
初始阶段 → 传播阶段 → 控制阶段 → 集成阶段 → 数据管理阶段 → 成熟阶段
  ←——— 计算机时代 ———→  ↑转折点  ←———— 信息时代 ————→
                  信息资源规划
```

| 阶段 | 时代归属 | 关键特征 |
|------|---------|---------|
| 1. 初始阶段 | 计算机时代 | 组织引入第一台计算机，少数人使用 |
| 2. 传播阶段 | 计算机时代 | 计算机应用扩散到多个部门，费用快速增长 |
| 3. 控制阶段 | 计算机时代 | 开始对IT支出进行控制，建立数据中心 |
| **转折点** | — | **信息资源规划**，从技术导向转向数据导向 |
| 4. 集成阶段 | 信息时代 | 统一规划，整合各分散系统 |
| 5. 数据管理阶段 | 信息时代 | 数据成为战略资源，建立数据库和数据中心 |
| 6. 成熟阶段 | 信息时代 | 信息系统与组织战略完全融合 |

> **记忆口诀**：初传控集数成；前三计算机，后三信息时代，转折在规划

#### 信息系统分类

从低级到高级排列：

| 系统类型 | 英文缩写 | 全称 | 层级 |
|---------|---------|------|------|
| 业务处理系统 | TPS/DPS | Transaction/Data Processing System | 最底层 |
| 管理信息系统 | MIS | Management Information System | 中层 |
| 决策支持系统 | DSS | Decision Support System | 中高层 |
| 专家系统 | ES | Expert System | 高层 |
| 办公自动化系统 | OAS | Office Automation System | 各层级 |

#### ⭐ 信息系统生命周期 — 高频考点

**4 个主要阶段**：

```
产生阶段 → 开发阶段 → 运行阶段 → 消亡阶段
              ↓
       5 个开发子阶段：
       总体规划 → 系统分析 → 系统设计 → 系统实施 → 系统验收
```

| 阶段 | 主要活动 |
|------|---------|
| 产生阶段 | 识别需求、可行性研究 |
| 开发阶段 | 总体规划→系统分析→系统设计→系统实施→系统验收 |
| 运行阶段 | 系统维护、性能监控、用户支持 |
| 消亡阶段 | 系统退役、数据迁移 |

> **记忆口诀**：产开运消；开发五步：总分设实收

#### ⭐ 信息系统建设原则 — 高频考点

| 原则 | 说明 |
|------|------|
| 高层管理人员介入 | 系统建设必须有高层领导的支持和参与 |
| 用户参与开发 | 用户全程参与，确保系统满足实际需求 |
| 自顶向下规划 | 从整体到局部，从战略到操作 |
| 工程化原则 | 采用工程化方法进行系统开发 |

#### ⭐ 信息系统开发方法 — 高频考点

| 方法 | 核心思想 | 特点 |
|------|---------|------|
| **结构化方法** | 自顶向下、逐步求精 | **最成熟、应用最广泛**；强调阶段性和文档化 |
| **原型法** | 快速构建原型，迭代改进 | 适合需求不明确的系统；用户参与度高 |
| **面向对象方法** | 以对象为核心，封装/继承/多态 | 可重用性好，符合人类思维方式 |
| **面向服务方法** | 以松耦合服务为基本单元 | 服务可独立部署、组合和重用 |

### 3.2 业务处理系统（TPS）

#### 概念

- TPS 是服务于组织**最底层**、**最基础**的信息系统
- 也称为**电子数据处理系统（EDP, Electronic Data Processing）**
- 主要处理日常业务操作中的大量重复性事务

#### ⭐ 数据处理方式对比 — 高频考点

| 对比维度 | 批处理（Batch Processing） | 联机事务处理（OLTP） |
|---------|-------------------------|-------------------|
| 处理方式 | 定期批量处理 | 实时逐笔处理 |
| 时效性 | 延迟处理，主文件**易过时** | 即时处理，数据**实时更新** |
| 成本 | **经济**，设备要求低 | **成本高**，设备要求高 |
| 适用场景 | 工资计算、账单处理等 | 银行交易、机票预订等 |
| 主文件状态 | 处理间隔内可能过时 | 始终保持最新 |
| 错误处理 | 批量发现，批量修正 | 即时发现，即时修正 |

> **记忆要点**：批处理经济但过时，OLTP 实时但昂贵

#### TPS 的 5 个处理阶段

```
数据输入 → 数据处理 → 数据库维护 → 文件报表生成 → 查询处理
```

#### TPS 的特点与地位

- **信息产生器**：TPS 是其他信息系统（MIS、DSS 等）的数据来源
- **企业与外部环境的桥梁**：连接组织内部运营与外部客户/供应商
- 处理的数据量大、重复性高、结构化程度高

### 3.3 管理信息系统（MIS）

#### 概念

- 在 **TPS 基础上**发展而来，对数据进行综合处理以支持管理决策
- **四大部件**：

| 部件 | 说明 |
|------|------|
| **信息源** | 数据的来源（内部/外部） |
| **信息处理器** | 对数据进行加工处理 |
| **信息用户** | 使用信息的管理者 |
| **信息管理者** | 负责系统运行维护的人员 |

> **记忆口诀**：源处用管

#### ⭐ MIS 的结构 — 高频考点

**按处理方式分类**：

| 结构类型 | 处理方式 | 特点 |
|---------|---------|------|
| **开环结构** | 批处理系统 | 系统输出不反馈到输入端，无实时监控 |
| **闭环结构** | 实时处理系统 | 系统输出反馈到输入端，可实时调控 |

**金字塔式结构**（纵向 × 横向）：

```
        ┌──────────────────┐
        │    战略计划层     │  ← 高层管理
        ├──────────────────┤
        │   管理控制层      │  ← 中层管理
        ├──────────────────┤
        │   运行控制层      │  ← 基层管理
        └──────────────────┘
     销售  生产  后勤  人事  财务 ...  （职能维度）
```

#### MIS 的 7 个职能子系统

| 序号 | 子系统 | 主要功能 |
|:---:|--------|---------|
| 1 | 销售市场子系统 | 销售预测、市场分析 |
| 2 | 生产子系统 | 生产计划、质量控制 |
| 3 | 后勤子系统 | 采购、库存、运输 |
| 4 | 人事子系统 | 招聘、培训、薪酬 |
| 5 | 财务会计子系统 | 财务核算、预算管理 |
| 6 | 信息处理子系统 | 数据处理、系统维护 |
| 7 | 高层管理子系统 | 战略规划、决策支持 |

### 3.4 决策支持系统（DSS）

#### 概念

- 帮助决策者解决**半结构化和非结构化**问题的交互式计算机系统
- **辅助**决策而非**替代**决策

#### DSS 的发展历程

```
模型库 + 数据库 + 人机交互
        ↓
增加知识库 + 方法库
        ↓
智能 DSS（IDSS）
        ↓
群体 DSS（GDSS）
        ↓
分布式 DSS（DDSS）
```

#### ⭐ DSS 两库结构 — 高频考点

| 子系统 | 功能 |
|--------|------|
| **数据库子系统** | 存储和管理决策所需的数据 |
| **模型库子系统** | 存储和管理各种决策模型（数学模型、仿真模型等） |
| **对话子系统** | 提供人机交互界面，连接用户与数据库/模型库 |

> **注意**：核心是"两库"（数据库 + 模型库），对话子系统是连接纽带

#### DSS 的特征

| 特征 | 说明 |
|------|------|
| 面向决策者 | 直接服务于中高层管理者 |
| 支持半结构化问题 | 处理不完全确定的决策问题 |
| 辅助而非替代 | 帮助决策者，不取代人的判断 |
| 动态性 | 能适应环境变化，灵活调整 |
| 交互式处理 | 人机频繁交互，迭代探索 |

#### 数据仓库与数据挖掘

数据挖掘的 4 种结果类型：

| 类型 | 说明 | 示例 |
|------|------|------|
| **联合**（Association） | 发现项之间的关联规则 | 购物篮分析 |
| **定序**（Sequence） | 发现时间序列上的模式 | 客户购买序列 |
| **分类**（Classification） | 将数据归入预定义类别 | 信用评分 |
| **聚类**（Clustering） | 将数据自动分组 | 客户细分 |

### 3.5 专家系统（ES）

#### ⭐ 核心公式 — 高频考点

| 对比 | 传统程序 | 专家系统 |
|------|---------|---------|
| 公式 | **数据结构 + 算法 = 程序** | **知识 + 推理 = 系统** |
| 核心 | 数据处理 | 知识处理 |

> **这是专家系统最本质的特征，考试必考**

#### ⭐ 专家系统的组成 — 高频考点

| 组成部分 | 性质 | 说明 |
|---------|------|------|
| **知识库** | 静态 | 存储领域专家的知识和经验 |
| **综合数据库** | 动态 | 存储推理过程中的当前信息（又称黑板/工作存储器） |
| **推理机** | **核心** | 利用知识库中的知识进行推理 |
| 知识获取 | — | 从专家处获取知识并录入知识库 |
| 解释程序 | — | 向用户解释推理过程和结论 |
| 人机接口 | — | 用户与系统交互的界面 |

> **记忆要点**：知识库是静态的，综合数据库是动态的，推理机是核心

#### ⭐ 推理方式 — 高频考点

| 推理方式 | 别名 | 方向 | 适用场景 |
|---------|------|------|---------|
| **正向推理** | 数据驱动 | 从事实→结论 | 已知条件多，探索可能结论 |
| **反向推理** | 目标驱动 | 从结论→事实 | 有明确假设，需要验证 |
| **双向推理** | 混合推理 | 正向+反向结合 | 复杂问题，效率更高 |

#### 专家系统的特点

| 特点 | 说明 |
|------|------|
| 超越时间限制 | 知识不会随时间退化，24小时可用 |
| 操作成本低廉 | 一次开发，多次使用 |
| 易于传递复制 | 知识可以方便地复制和传播 |
| 处理手段一致 | 对同类问题给出一致的处理结果 |
| 善于克服难题 | 综合运用多种知识解决问题 |
| 适用特定领域 | 在特定领域表现出色，通用性差 |

### 3.6 办公自动化系统（OAS）

- **四大支柱**：

| 支柱 | 说明 |
|------|------|

| 通信技术 | 信息传输与网络 |
| 系统科学 | 系统分析与设计方法 |

#### 三大功能

| 功能 | 说明 |
|------|------|
| 事务处理 | 文档管理、日程安排、邮件处理 |
| 信息管理 | 信息收集、存储、检索 |
| 辅助决策 | 提供信息支持管理决策 |

#### OAS 的组成

| 组成部分 | 内容 |
|---------|------|

| 软件系统 | 办公软件、协同工具、管理系统 |

### 3.7 企业资源规划（ERP）

#### ⭐ ERP 概念与发展 — 高频考点

**发展路径**：

```
MRP（物料需求计划）→ MRP-II（制造资源计划）→ ERP（企业资源规划）
```

**核心思想**：对企业的**三大流**进行全面集成管理：

| 流 | 说明 |
|----|------|
| **物流** | 原材料采购→生产→产品销售的实体流动 |
| **资金流** | 伴随物流的资金运动 |
| **信息流** | 贯穿全程的信息传递与处理 |

#### ⭐ ERP 的 5 个层次计划 — 高频考点

```
经营计划（最高层）
    ↓
生产计划大纲
    ↓
主生产计划（MPS）
    ↓
物料需求计划（MRP）
    ↓
车间作业计划（PAC）（最底层）
```

| 层次 | 名称 | 主要内容 | 时间跨度 |
|:---:|------|---------|---------|
| 1 | **经营计划** | 企业总体战略目标 | 3-5 年 |
| 2 | **生产计划大纲** | 产品大类的生产总量 | 1-3 年 |
| 3 | **主生产计划 MPS** | 具体产品的生产数量和时间 | 数月 |
| 4 | **物料需求计划 MRP** | 零部件和原材料的需求 | 数周 |
| 5 | **车间作业计划 PAC** | 车间的具体加工任务 | 日/班次 |

> **记忆口诀**：经大主物车

#### ERP 的 11 个基本模块

| 序号 | 模块 | 序号 | 模块 |
|:---:|------|:---:|------|
| 1 | 生产预测 | 7 | 车间作业计划 |
| 2 | 销售管理 | 8 | 采购与库存管理 |
| 3 | 经营计划 | 9 | 质量与设备管理 |
| 4 | 主生产计划 | 10 | 财务管理 |
| 5 | 物料需求计划 | 11 | 扩展应用模块 |
| 6 | 能力需求计划 | | |

#### ERP 的核心功能

- 支持企业决策（提供全面信息）
- 提供行业解决方案（针对不同行业定制）
- 全行业供应链管理（整合上下游资源）

### 3.8 典型信息系统架构模型

#### ⭐ 电子政务 — 高频考点

**3 个组成部分**：

| 组成部分 | 说明 |
|---------|------|
| 政府内部网络化 | 政府部门内部的信息化建设 |
| 政府间通信 | 不同政府部门之间的信息交换 |
| 政府与居民双向交流 | 政府向公众提供服务，公众参与政务 |

**⭐ 5 个互动领域**：

| 缩写 | 全称 | 说明 |
|------|------|------|
| **G2G** | Government to Government | 政府与政府之间 |
| **G2B** | Government to Business | 政府对企业 |
| **G2C** | Government to Citizen | 政府对公民 |
| **B2G** | Business to Government | 企业对政府 |
| **C2G** | Citizen to Government | 公民对政府 |

> **记忆要点**：G（政府）、B（企业）、C（公民）三者之间的两两互动

**4 个发展阶段**：

```
起步阶段 → 单向互动阶段 → 双向互动阶段 → 网上事务处理阶段
```

| 阶段 | 特征 |
|------|------|
| 起步阶段 | 政府网站建立，发布静态信息 |
| 单向互动 | 政府提供在线表格下载等单向服务 |
| 双向互动 | 政府与公众可在线互动交流 |
| 网上事务处理 | 完整在线业务办理（最高阶段） |

## 易混淆点对比表格

### 对比表 1：TPS vs MIS vs DSS vs ES vs OAS

| 对比维度 | TPS | MIS | DSS | ES | OAS |
|---------|-----|-----|-----|-----|-----|
| **服务对象** | 基层操作人员 | 中基层管理者 | 中高层决策者 | 各领域用户 | 办公人员 |
| **处理问题类型** | 结构化 | 结构化 | 半结构化/非结构化 | 非结构化 | 结构化/半结构化 |
| **主要功能** | 日常事务处理 | 信息管理与报表 | 辅助决策 | 模拟专家决策 | 办公事务管理 |
| **数据特点** | 大量、详细、原始 | 汇总、综合 | 内外部数据结合 | 知识规则 | 文档、邮件 |
| **输出形式** | 报表、单据 | 定期报表 | 分析报告、建议 | 推理结论+解释 | 文档、日程 |
| **系统层级** | 最底层 | 中层 | 中高层 | 高层 | 各层级 |

### 对比表 2：批处理 vs 联机事务处理

| 对比维度 | 批处理（Batch） | 联机事务处理（OLTP） |
|---------|---------------|-------------------|
| 处理时机 | 定期、成批处理 | 实时、逐笔处理 |
| 数据更新 | 延迟更新 | 即时更新 |
| 主文件状态 | 处理间隔内**易过时** | 始终**保持最新** |
| 成本 | **经济**，设备要求低 | **昂贵**，设备要求高 |
| 响应速度 | 慢（等待批处理执行） | 快（即时响应） |
| 典型应用 | 工资计算、月末结算 | 银行交易、航空订票 |
| 并发要求 | 低 | 高（需处理并发事务） |

### 对比表 3：开环系统 vs 闭环系统

| 对比维度 | 开环系统 | 闭环系统 |
|---------|---------|---------|
| 处理方式 | 批处理 | 实时处理 |
| 反馈机制 | **无反馈**，输出不影响输入 | **有反馈**，输出可调节输入 |
| 实时性 | 低 | 高 |
| 适用场景 | 数据量小、时效要求低 | 需要实时监控和调控 |
| 典型应用 | 月末财务报表 | 生产过程控制系统 |

### 对比表 4：结构化方法 vs 原型法 vs 面向对象方法 vs 面向服务方法

| 对比维度 | 结构化方法 | 原型法 | 面向对象方法 | 面向服务方法 |
|---------|-----------|--------|------------|------------|
| **核心思想** | 自顶向下，逐步求精 | 快速构建原型 | 对象封装/继承/多态 | 松耦合服务组合 |
| **成熟度** | **最成熟最广泛** | 较成熟 | 成熟 | 新兴 |
| **需求处理** | 需求明确后开发 | 需求不明确时适用 | 迭代式需求 | 服务契约驱动 |
| **用户参与** | 阶段性参与 | **高度参与** | 迭代参与 | 有限参与 |
| **文档** | **文档要求严格** | 文档较少 | 适度文档 | 服务描述为主 |
| **可重用性** | 低 | 低 | **高** | **最高** |
| **适用规模** | 大中型项目 | 小型项目/子系统 | 各种规模 | 分布式系统 |

### 对比表 5：ERP 计划 5 个层次对比

| 层次 | 计划名称 | 规划对象 | 时间跨度 | 详细程度 | 管理层级 |
|:---:|---------|---------|---------|---------|---------|
| 1 | 经营计划 | 企业整体战略 | 3-5 年 | 最粗 | 最高层 |
| 2 | 生产计划大纲 | 产品大类产量 | 1-3 年 | 较粗 | 高层 |
| 3 | 主生产计划 MPS | 具体产品品种 | 数月 | 中等 | 中层 |
| 4 | 物料需求计划 MRP | 零部件/原材料 | 数周 | 较细 | 基层 |
| 5 | 车间作业计划 PAC | 加工工序/工位 | 日/班次 | **最细** | 操作层 |

> **关键关系**：上层计划驱动下层计划，下层反馈约束上层计划

### 对比表 6：电子政务 5 个互动领域

| 缩写 | 全称 | 方向 | 典型应用 |
|------|------|------|---------|
| **G2G** | Government to Government | 政府↔政府 | 跨部门数据共享、联合审批 |
| **G2B** | Government to Business | 政府→企业 | 电子采购、企业注册、税务申报 |
| **G2C** | Government to Citizen | 政府→公民 | 社保查询、证件办理、信息公开 |
| **B2G** | Business to Government | 企业→政府 | 企业报税、投标报价、合规报告 |
| **C2G** | Citizen to Government | 公民→政府 | 在线投诉、民意调查、政策建议 |

> **注意区分**：G2B（政府主动服务企业）vs B2G（企业主动向政府提交），方向不同
