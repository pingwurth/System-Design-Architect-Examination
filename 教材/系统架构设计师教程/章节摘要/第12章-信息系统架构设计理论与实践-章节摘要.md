## 一、信息系统架构基本概念 ⭐⭐

### 1.1 定义

> 信息系统架构（ISA）是软件/计算机系统的**结构**，由**软件元素**、元素的**外部可见属性**及它们之间的**关系**组成。

**定义要点**：
- 架构是对系统的**抽象**，强调"外部可见"属性（非内部实现细节）
- 架构由**多个结构**组成，单个结构一般不能代表完整架构
- 架构可以**独立于文档**存在（文档可能过时）
- 架构具有**基础性**：涉及通用方案和影响深远的决策
- 架构隐含**决策**：由架构师根据功能/非功能需求设计

### 1.2 两个层次

| 层次 | 说明 |
|------|------|
| **概念层次** | 艺术、科学、方法和建设风格 |
| **物理层次** | 物理结构及其相互作用的结果 |

### 1.3 架构的商业周期

影响因素 → 架构决策 → 架构实现 → 反作用（影响组织结构、商机）→ 影响下一轮需求

### 1.4 发展历史 ⭐

| 时间 | 事件 |
|------|------|
| 1980s中期 | **John Zachman**（IBM）提出"信息系统架构框架"概念；6个视角×6个模型 |
| 1999年 | 美国联邦CIO委员会公布**联邦企业架构框架**（FEAF） |
| 此后 | **TOGAF**成为最著名的行业标准企业架构框架 |

## 二、信息系统架构分类 ⭐⭐

### 2.1 物理结构（硬件空间分布）

| 类型 | 优点 | 缺点 |
|------|------|------|
| **集中式** | 资源集中、便于管理、利用率高 | 维护困难、系统脆弱（单点故障） |
| **分布式** | 灵活扩展、安全性好、容错 | 标准不统一、协调困难 |

> **分布式已成主流**，分为一般分布式和客户机/服务器模式。

### 2.2 逻辑结构（功能综合体）

| 综合方式 | 说明 | 示例 |
|----------|------|------|
| **横向综合** | 同一管理层次的各种职能综合 | 运行控制层的人事+工资子系统 |
| **纵向综合** | 某种职能的各管理层次综合 | 工厂会计+公司会计系统 |
| **纵横综合** | 信息集中共享+程序模块化 | 公用数据库+统一信息处理系统 |

## 三、信息系统常用4种架构模型 ⭐⭐⭐

### 3.1 单机应用模式（Standalone）

运行在一台物理机器上的独立应用程序，可以是多进程/多线程。如CAD/CAM、Photoshop等。

### 3.2 客户机/服务器（C/S）模式 ⭐⭐

| 层级 | 说明 | 特点 |
|------|------|------|
| **两层C/S** | 前台客户端+后台数据库；"胖客户端" | 客户端集成界面+业务逻辑 |
| **三层C/S** | 前台界面+后台服务+业务逻辑层 | 需协议通信（TCP/RPC/CORBA/RMI/HTTP等） |
| **B/S** | 浏览器+Web服务器+后台 | 通用客户端界面，基于HTTP，本质是三层C/S |
| **多层C/S** | 三层以上（含中间件/应用服务器层） | 提高可伸缩性、隔离数据库访问 |

**三层C/S七种通信协议**：
1. 基于TCP/IP Socket自开发
2. 自定义消息机制（XML/字节流）
3. RPC编程
4. CORBA/IIOP协议
5. Java RMI
6. J2EE JMS
7. HTTP协议

**中间件层三大作用**：
1. 提高可伸缩性和并发性能
2. 处理复杂企业逻辑（请求代理/应用服务器）
3. 增加数据安全性（隔离Web服务器对数据库的直接访问）

### 3.3 MVC模式 ⭐

| 组件 | 对应层次 | 职责 |
|------|----------|------|
| **View（视图）** | 浏览器层 | 图形化展示 |
| **Controller（控制器）** | Web服务器层 | 连接模型和视图 |
| **Model（模型）** | 应用逻辑+数据持久化 | 业务逻辑和数据 |

> MVC本质是多层C/S的标准化模式；控制器和视图通常在Web服务器一层。

### 3.4 面向服务架构（SOA）与多服务集合 ⭐⭐

| 要素 | 内容 |
|------|------|
| **SOA定义** | 多个独立应用系统通过消息通信相互协作 |
| **"服务"含义** | 不是Daemon，而是提供完整功能的**独立应用系统** |
| **SOA本质** | **消息机制或远程过程调用（RPC）** |
| **Web Service** | SOA在Web应用上的体现；协议：SOAP + WSDL |
| **实现方式** | 通常借助中间件（消息中间件、交易中间件） |

### 3.5 企业数据交换总线 ⭐

| 要素 | 内容 |
|------|------|
| 实质 | **连接器**（Connector）软件系统 |
| 基础 | 可基于消息/交易中间件或CORBA/IIOP |
| 功能 | 数据/请求/回复的接收与分发 |
| 应用 | 银行、电信等高信息化行业 |
| 特点 | 主要为**实时交易**设计；大数据量传输需单独设计 |

> 若采用CORBA协议，交换总线就是**对象请求代理（ORB）**，也称"代理（Agent）体系"。

## 四、企业信息系统总体框架 ⭐⭐⭐

### 4.1 四部分组成

| 层次 | 组成 | 说明 |
|------|------|------|
| **第一层** | **战略系统** | 高层决策支持+战略规划 |
| **第二层** | **业务系统** + **应用系统** | 业务过程优化+计算机实现手段 |
| **第三层** | **信息基础设施** | 技术+信息资源+管理基础 |

### 4.2 战略系统

- **高层决策支持系统**（计算机辅助）
- **企业战略规划体系**（长期规划+短期规划）

### 4.3 业务系统

- 由**业务过程**→**业务活动**构成
- 核心方法：**业务流程重组（BPR）** — 以业务流程为中心，打破部门分工
- BPR效果：经济效率可提高**70%-80%**

### 4.4 应用系统

| 系统类型 | 缩写 |
|----------|------|
| 事务处理系统 | TPS |
| 管理信息系统 | MIS |
| 决策支持系统 | DSS |
| 专家系统 | ES |
| 办公自动化系统 | OAS |
| CAD/CAPP/CAM | |
| 制造资源计划 | MRP II |

> 每个应用系统包含两个基本部分：**内部功能实现部分**和**外部界面部分**。

### 4.5 企业信息基础设施（EII）⭐

| 设施类型 | 组成 | 变化程度 |
|----------|------|----------|
| **技术基础设施** | 计算机、网络、系统软件、协议 | 变化**较多** |
| **信息资源设施** | 数据、标准、处理方法 | 变化**较少** |
| **管理基础设施** | 组织结构、人员分工、规章制度 | 变化**较多** |

## 五、ADM架构开发方法 ⭐⭐⭐

### 5.1 TOGAF概述

| 要素 | 内容 |
|------|------|
| 全称 | The Open Group Architecture Framework |
| 来源 | 1995年发表；基础是美国国防部TAFIM |
| 特点 | 开放式标准、免费使用（内部）、迭代过程模型 |
| 核心 | **ADM（架构开发方法）** |

**TOGAF v9 六大组件**：
1. 架构开发方法（ADM）— **核心**
2. ADM指南和技术
3. 架构内容框架
4. 企业连续体和工具
5. TOGAF参考模型（TRM + III-RM）
6. 架构能力框架

**TOGAF四个目标**：
1. 统一语言，消除沟通障碍
2. 避免被锁定到专有方案
3. 节省时间和金钱
4. 实现可观的投资回报（ROI）

### 5.2 ADM全生命周期 — 十个阶段 ⭐⭐⭐

| 阶段 | 名称 | 主要活动 |
|------|------|----------|
| **准备阶段** | Preliminary | 定义组织、框架、原则、工具 |
| **需求管理** | Requirements Management | **贯穿所有阶段**；识别、存储、交付需求 |
| **阶段A** | **架构愿景** | 设置范围/约束/期望；创建架构愿景；获得批准 |
| **阶段B** | **业务架构** | 开发基线/目标业务架构；差距分析 |
| **阶段C** | **信息系统架构** | **数据架构** + **应用架构**（可并行） |
| **阶段D** | **技术架构** | 物理实现（硬件/软件/通信技术） |
| **阶段E** | **机会和解决方案** | 初步实施规划；确定构建块交付物形式 |
| **阶段F** | **迁移规划** | 制定详细实施和迁移计划 |
| **阶段G** | **实施治理** | 架构约束、监督、架构契约 |
| **阶段H** | **架构变更管理** | 持续监测和变更管理 |

> **ADM三级迭代**：
> 1. 基于ADM整体的环形迭代
> 2. 多个开发阶段间的迭代（如技术架构→业务架构）
> 3. 一个阶段内部的迭代

### 5.3 各阶段详细说明

#### 阶段B — 业务架构（核心）
- 开发**基线**业务架构描述
- 开发**目标**业务架构描述
- 执行**差距分析**
- 核心内容：组织如何满足业务目标；静态特征（目标/组织/角色）+动态特征（流程/功能/服务）

#### 阶段C — 信息系统架构（两步）
- **数据架构**：定义数据源、数据类型、数据模型
- **应用架构**：定义处理数据的应用系统

#### 阶段D — 技术架构
- 将应用组件**映射**为技术组件（硬件/软件）
- 定义物理实现

#### 阶段E — 机会和解决方案
- **第一个直接关注实施的阶段**
- 合并B-D阶段差距分析
- 确定途径：制造/购买/重用/外包/商用/开源
- 识别过渡架构

#### 阶段F — 迁移规划
- 绩效分析+风险评估
- 划分工作包优先级（业务价值+成本分析）
- 生成有时间标识的架构实现路线图

#### 阶段G — 实施治理
- 定义架构约束
- 发布架构契约
- 确保实施符合架构

#### 阶段H — 架构变更管理
- 持续监测
- 评估架构性能
- 管理变更流程

#### 需求管理 — ADM的中心 ⭐

> 需求管理适用于ADM的**所有阶段**，是ADM流程的**中心**。

### 5.4 架构活动范围的四个维度 ⭐

| 维度 | 考察内容 |
|------|----------|
| **企业范围或焦点** | 业务覆盖范围 |
| **架构领域** | 业务/数据/应用/技术四个领域 |
| **详述垂直范围或级别** | 细化到第几层 |
| **时间周期** | 架构愿景的时间范围 |

## 六、信息化总体架构方法 ⭐⭐

### 6.1 信息化概念

| 要素 | 内容 |
|------|------|
| 起源 | 1960s日本，梅棹忠夫提出 |
| 中国定义（1997） | 培育、发展以智能化工具为代表的新生产力 |
| 国家信息化6要素 | 信息资源、信息网络、信息技术应用、信息技术产业、信息化人才、信息化政策 |
| 信息化内涵4方面 | 信息网络体系、信息产业基础、社会运行环境、效用积累过程 |

### 6.2 信息化6种特征

| 特征 | 要点 |
|------|------|
| **易用性** | 最重要，能否帮助客户成功应用 |
| **健壮性** | 最大并发用户数、数据量 |
| **平台化/灵活性/拓展性** | 不修改源代码即可搭建功能模块 |
| **安全性** | 加密、权限管理、电子签章 |
| **门户化/整合性** | 统一管理平台 |
| **移动性** | 手机等移动终端支持 |

### 6.3 信息化架构两种模式 ⭐

| 模式 | 关注点 | 切入点 | 代表技术 |
|------|--------|--------|----------|
| **数据导向** | 数据对象和数据关系 | 主题域分析→业务对象→关系 | MDM（主数据管理）、BI |
| **流程导向** | 端到端流程整合 | 价值链分析→流程分解→业务组件 | SOA、BPEL |

> **两者相互配合和补充**，无严格边界。数据导向缺完整数据模型时导致数据质量管理问题；流程导向缺组合服务能力时导致数据分散。

### 6.4 信息化建设生命周期 — 五阶段 ⭐

| 阶段 | 核心任务 | 产出物 |
|------|----------|--------|
| **系统规划** | 环境调查、需求分析、可行性研究 | 可行性分析报告、系统设计任务书 |
| **系统分析** | 详细调查、确定逻辑功能；**回答"做什么"** | **系统说明书**（关键文件） |
| **系统设计** | 设计技术方案；**回答"怎么做"** | 系统设计说明书 |
| **系统实施** | 购置设备、编程、培训、数据转换 | 实施进度报告、测试分析报告 |
| **系统运行和维护** | 维护、评价、修改 | 运行记录 |

> **系统分析**是整个系统建设的**关键阶段**，也是信息系统建设与一般工程项目的**重要区别**所在。

### 6.5 信息化工程总体规划三大方法 ⭐⭐

| 方法 | 英文 | 核心思想 | 特点 |
|------|------|----------|------|
| **关键成功因素法** | CSF | 识别影响系统目标的关键因素→确定优先级 | **抓住主要矛盾**，快速明确目标 |
| **战略目标集转化法** | SST | 把战略目标看作"信息集合"→转化为IS战略目标 | **目标全面**，疏漏少；但**不突出重点** |
| **企业系统规划法** | BSP | 自上而下识别目标/过程/数据→自下而上设计IS | 无明显目标导引；通过**企业过程/数据类矩阵**转化 |

## 七、案例分析 ⭐⭐

### 7.1 案例一：价值驱动的体系结构

**核心概念**：

| 概念 | 说明 |
|------|------|
| **价值模型** | 三种基本形式：价值期望值、反作用力、变革催化剂 |
| **价值驱动因素** | 反作用力+变革催化剂（限制因素） |
| **体系结构挑战** | 限制因素使满足期望值变困难 |
| **体系结构策略** | 简短高标准方向陈述，在系统生存期保持相对稳定 |

**体系结构策略四个领域**：
1. **组织**：子系统如何组织、部署、连接
2. **操作**：组件如何交互（同步/异步）、错误处理
3. **可变性**：哪些功能可随部署环境变化
4. **演变**：如何支持变更同时保持稳定

**价值模型与软件架构的9点联系**（核心3点）：
- 系统存在是为了提供价值
- 体系结构挑战由环境因素引起
- 体系结构方法首先克服最高优先级挑战来实现价值最大化

### 7.2 案例二：Web服务在HL7上的应用

| 要素 | 内容 |
|------|------|
| **HL7** | Health Level Seven，卫生保健信息交换标准（OSI应用层） |
| **RIM** | 参考信息模型，HL7 V3的基础 |
| **消息结构** | Transmission Wrapper封装；通过SOAP传输 |
| **交互** | 触发事件→消息转移→应用接收/发送 |
| **体系结构** | 商业逻辑 + Web服务适配器（发送端/接收端） |
| **案例** | HIS（医疗信息系统）↔ LIS（实验室信息系统）交互 |

**开发HL7 Web服务适配器步骤**：
1. 消息和数据类型设计
2. 适配器模式选择
3. HL7 Web服务契约开发（WSDL）
4. 产生Web服务Stub和代理
5. 开发适配器业务逻辑

### 7.3 案例三：以服务为中心的企业整合

| 要素 | 内容 |
|------|------|
| **背景** | 航空公司，异构系统（主机/UNIX/.Net）；Information Hub有缺陷 |
| **方法** | 组件业务建模（CBM）+ 面向服务建模和架构（SOMA） |
| **服务类型** | 信息服务（Federation）、流程服务（BPEL4WS）、Staff Service |
| **ESB** | 企业服务总线：事件服务（Pub/Sub）、传输服务（WSIF） |
| **核心价值** | 服务可替换性；降低耦合性；流程编排灵活性 |

**服务建模输出示例**：
- Retrieve Flight BO → 信息服务（Federation Service）
- Ramp Coordination → 流程服务（BPEL4WS）
- Check Spot/Unloading/Loading/Push Back → Staff Service

## 易混淆点对比

### 对比1：物理结构 vs 逻辑结构

| 维度 | 物理结构 | 逻辑结构 |
|------|----------|----------|
| 关注点 | 硬件空间分布 | 功能子系统综合体 |
| 分类 | 集中式/分布式 | 横向/纵向/纵横综合 |
| 变化 | 较少 | 较多 |

### 对比2：两层C/S vs 三层C/S vs B/S

| 维度 | 两层C/S | 三层C/S | B/S |
|------|---------|---------|-----|
| 客户端 | 胖客户端（含业务逻辑） | 瘦客户端 | 浏览器（通用） |
| 业务逻辑 | 在客户端 | 在中间层 | 在Web服务器 |
| 维护成本 | 高 | 中 | **低** |
| 本质 | IPC结构 | 分层结构 | 三层C/S的标准客户端 |

### 对比3：SOA vs 多层C/S

| 维度 | 多层C/S | SOA |
|------|---------|-----|
| 范围 | 单结点应用 | 多个独立应用系统 |
| 通信 | 层间协议 | 应用间消息/RPC |
| 粒度 | 细（层内组件） | 粗（整个应用系统） |
| 典型 | J2EE多层结构 | Web Service、ESB |

### 对比4：CSF vs SST vs BSP

| 维度 | CSF | SST | BSP |
|------|-----|-----|-----|
| 切入点 | 关键成功因素 | 战略目标集合 | 企业过程/数据类 |
| 优点 | **突出重点**，快速明确目标 | **全面**，疏漏少 | 适应性广 |
| 缺点 | 可能遗漏次要目标 | **不突出重点** | 无明显目标导引 |
| 最适合 | 确定管理目标 | 目标全面性 | 大型系统整体规划 |

### 对比5：数据导向 vs 流程导向架构

| 维度 | 数据导向 | 流程导向 |
|------|----------|----------|
| 关注点 | 数据对象和关系 | 端到端流程整合 |
| 切入方法 | 主题域分析 | 价值链分析 |
| 代表技术 | MDM、BI | SOA、BPEL |
| 风险 | 缺少完整流程视图 | 缺少完整数据模型 |
| 关系 | **相互配合和补充** | **相互配合和补充** |

## 高频考点速查 ⭐

1. **ISA定义三要素**：软件元素 + 外部可见属性 + 关系
2. **Zachman框架**：6视角（信息/流程/网络/人员/时间/原理）× 6模型
3. **分布式结构**已成主流，分一般分布式和C/S模式
4. **逻辑结构三种综合**：横向、纵向、纵横
5. **四种架构模型**：单机、C/S（两层/三层/多层/B/S）、SOA、企业数据交换总线
6. **B/S本质**：采用通用客户端界面的三层C/S结构
7. **MVC**：View(展示) + Controller(连接) + Model(业务逻辑)
8. **SOA本质**：消息机制或RPC
9. **企业IS框架四层**：战略系统 → 业务系统+应用系统 → 信息基础设施
10. **EII三部分**：技术基础设施（变化多）+ 信息资源设施（变化少）+ 管理基础设施（变化多）
11. **ADM十阶段**：准备→需求管理→A愿景→B业务→C信息系统→D技术→E机会→F迁移→G治理→H变更
12. **需求管理是ADM的中心**，贯穿所有阶段
13. **阶段E是第一个直接关注实施的阶段**
14. **信息化生命周期五阶段**：规划→分析→设计→实施→运维
15. **系统分析是关键阶段**，回答"做什么"；系统设计回答"怎么做"
16. **三大规划方法**：CSF（突出重点）、SST（全面）、BSP（过程/数据矩阵）
17. **两种信息化架构模式**：数据导向（MDM）+ 流程导向（SOA），互补
18. **BPR效果**：经济效率提高70%-80%
19. **架构活动范围四维度**：企业范围、架构领域、详述级别、时间周期
20. **价值驱动架构**：价值期望值 + 反作用力 + 变革催化剂 = 价值驱动因素
