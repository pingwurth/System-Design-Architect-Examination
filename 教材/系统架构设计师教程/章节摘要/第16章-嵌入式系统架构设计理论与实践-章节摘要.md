## 一、嵌入式系统概述

### 1.1 嵌入式系统定义

为**特定应用**而专门构建的计算机系统，其软件架构与硬件体系结构密不可分。

### 1.2 发展历程（五个阶段）

| 阶段 | 名称 | 硬件 | 软件 | 主要特点 |
|------|------|------|------|----------|
| 1 | **SCM（单片微型计算机）** | 单片机 | 无OS，汇编语言 | 功能单一、效率低、存储小 |
| 2 | **MCU（微控制器）** | 嵌入式微处理器 | 简单OS | 智能化控制、种类多、系统开销小 |
| 3 | **SoC（片上系统）** | 各类微处理器 | 兼容性好 | 内核小、效率高 |
| 4 | **Internet 嵌入式** | 集成网络接口 | — | 嵌入式网络化 |
| 5 | **智能化/云技术** | — | — | 低能耗、高速度、高集成、高可信 |

### 1.3 硬件体系结构 ⭐⭐

#### 1.3.1 嵌入式微处理器（五种类型）

| 类型 | 缩写 | 特点 | 代表产品 |
|------|------|------|----------|
| **微处理器** | MPU | 专门电路板上，体积小/成本低，但需外接ROM/RAM/总线 | Am186/88、PowerPC、MIPS、ARM |
| **微控制器** | MCU | 单片机，**单片化**是最大优点，体积小/功耗低/可靠性高 | MCS-96/196/296、ARM系列 |
| **信号处理器** | DSP | **哈佛结构**，适合DSP算法，编译效率高 | TI TMS320系列、DSP56000 |
| **图形处理器** | GPU | 3D图形渲染，减少对CPU依赖 | — |
| **片上系统** | SoC | 大部分系统集成到一块或几块芯片 | — |

> **芯片工作温度等级：** 民用级 0~70℃、工业级 -40~85℃、军用级 -55~150℃

#### 1.3.2 存储器 ⭐⭐

**RAM（随机存取存储器）——断电丢失：**

| 类型 | 特点 | 应用 |
|------|------|------|
| **DRAM** | 最普通，需定期刷新（2~4ms），成本低 | 主存储器 |
| **SRAM** | 无需刷新，速度快、稳定，成本高 | 高速缓存 |
| **SDRAM** | 与CPU Clock同步，减少延迟 | 通用内存 |
| **DDR SDRAM** | 速度比SDRAM快一倍，采用DLL | 当前主流 |

**ROM（只读存储器）——断电不丢失：**

| 类型 | 特点 |
|------|------|
| **MASK ROM** | 一次性制造，不可修改，成本低 |
| **PROM** | 一次可编程（OTP） |
| **EPROM** | 紫外线擦除后可重写 |
| **EEPROM** | 电擦除（约20V），可电写入 |
| **Flash Memory** | 可在主板上修改，断电不丢失，写入速度慢 |

#### 1.3.3 总线 ⭐

**按连接部件分类（四种）：**

| 类型 | 位置 | 说明 |
|------|------|------|
| **片内总线** | CPU 芯片内部 | 连接ALU、寄存器、指令部件 |
| **系统总线** | 计算机内部 | 连接CPU、主存、I/O接口（又称板级总线/内部总线） |
| **局部总线** | 少数组件之间 | 如CPU到北桥，协议由设备制造商定义 |
| **通信总线** | 主机外部 | 连接外部设备或其他计算机系统（又称外部总线/外设总线） |

**总线拓扑结构（五种）：** 星形、树状、环形、总线型、交叉开关型

**总线传输信息类型：** 数据总线、地址总线、控制总线

#### 1.3.4 看门狗电路 ⭐

- 嵌入式系统**必须具备**的系统恢复能力
- **功能**：系统发生软件问题或程序跑飞后使系统**重新启动**
- **原理**：看门狗计数器正常工作时自动计数，程序定期将其复位；若系统卡死或跑飞，定时器溢出→进入中断→保留关键数据→系统复位重启

## 二、嵌入式软件架构原理与特征

### 2.1 两种典型架构模式 ⭐⭐⭐

#### 1. 层次化模式架构

| 特征 | 说明 |
|------|------|
| **核心思想** | 高层抽象依赖低层具体实现 |
| **封闭型** | 一层中对象只能调用**同层或下一层**对象，封装好/移植性好 |
| **开放型** | 一层中对象可调用**同层或任意低层**对象，性能较好但破坏封装 |

> **考试要点：** 封闭型移植性好，开放型性能较好。

#### 2. 递归模式架构

| 特征 | 说明 |
|------|------|
| **核心问题** | 将非常复杂的系统分解，确保分解过程**可扩展** |
| **实现方式** | 重复应用简单的包含关系 |
| **两种工作流** | **自顶向下**（从系统层级开始，基于标准方法分解子系统）；**自底向上**（从域中关键类和关系开始） |

### 2.2 嵌入式操作系统 ⭐⭐

#### 主要特点（12项）

可剪裁性、可移植性、**强实时性**、强紧凑性、高质量代码、强定制性、标准接口、**强稳定性/弱交互性**、强确定性、操作简洁、较强硬件适应性、可固化性

#### 分类

| 类型 | 代表产品 | 应用 |
|------|----------|------|
| **实时EOS** | VxWorks、Nucleus | 控制、通信 |
| **非实时EOS** | Android、iOS、WinCE | 消费电子 |

#### 内核架构对比 ⭐⭐⭐

| 对比维度 | **宏内核（Monolithic）** | **微内核（Micro）** |
|----------|--------------------------|---------------------|
| **地址空间** | 用户/内核服务**同一空间** | 用户/内核服务**不同地址空间** |
| **通信方式** | 直接调用 | 消息传递 |
| **性能** | 高 | 偏低（消息传递开销） |
| **耦合度** | 高 | 低 |
| **移植性** | 差 | 好（代码量少） |
| **伸缩性** | 差 | 好 |
| **代表** | VxWorks 5.5、VRTX | 嵌入式Linux、L4、WinCE |

#### 任务管理 ⭐⭐⭐

**任务三状态及转换：**

```
就绪 ←→ 执行 → 阻塞 → 就绪
  ↑(分配CPU)  ↓(时间片用完)  ↓(等待事件)  ↑(事件发生)
```

- **执行态**：已获得CPU，正在运行
- **就绪态**：已分配除CPU外所有资源，等待CPU
- **阻塞态**：等待某事件发生，放弃CPU

> **注意：** 阻塞态**不能**直接转执行态；就绪态**不能**直接转阻塞态。

#### 实时调度算法 ⭐⭐⭐（高频考点）

| 算法 | 类型 | 优先级规则 | 特点 |
|------|------|------------|------|
| **EDF（最早截止时间优先）** | 动态 | 截止时间越早，优先级越高 | 可用于抢占/非抢占 |
| **LLF（最低松弛度优先）** | 动态 | 松弛度=必须完成时间-运行时间-当前时间，越小优先级越高 | 主要用于抢占 |
| **RMS（单调速率调度）** | 静态 | 周期越短，优先级越高 | **最优静态算法**——若RMS不能调度，其他静态算法也不能 |

**松弛度计算公式：**
```
松弛度 = 必须完成时间（截止期限）- 本身运行时间 - 当前时间
```

#### 存储管理（5种方法） ⭐⭐

| 方法 | 核心思想 | 优点 | 缺点 |
|------|----------|------|------|
| **分区存储** | 内存分区域加载 | 管理简单 | 碎片、空间浪费 |
| **分页存储** | 逻辑/物理空间等分为页 | 无外部碎片、可共享 | 页表大、需硬件支持 |
| **分段存储** | 按逻辑单元分段 | 逻辑清晰、易共享 | 有外部碎片、段需全部加载 |
| **段页存储** | 先分段后分页 | 减少碎片、便于模块化 | 管理复杂、开销大 |
| **虚拟存储** | 内存+外存结合 | 突破内存限制 | 需硬件、有带宽瓶颈 |

**分区存储三种算法：**
- **首次适应**：找第一个满足的空闲区（可能造成碎片）
- **最佳适应**：找最小满足的空闲区（保护大区域）
- **最坏适应**：找最大空闲区分割（对中、小作业有利）

#### 任务间通信 ⭐⭐

| 方式 | 特点 | 适用 |
|------|------|------|
| **共享内存** | 最直接、最高效 | 简单数据共享 |
| **信号量** | 最快速的互斥和同步 | 同步/互斥 |
| **消息队列** | 更高级，可传递任意长度信息 | 带数据的通信和同步 |
| **Socket/远程调用** | 网络通信 | 跨计算机通信 |
| **Signals（信号）** | 异步通信，中断机制模拟 | 异常处理 |

**信号量三种类型：**
- 二进制信号量（最快，解决同步）
- 互斥信号量（互斥、优先级继承、递归）
- 计数信号量（多实例资源保护）

### 2.3 嵌入式数据库 ⭐

#### 特点（对比传统数据库）

嵌入式、实时性、移动性、伸缩性

#### 分类（按存储位置）

| 类型 | 核心特征 | 典型产品 |
|------|----------|----------|
| **基于内存（MMDB）** | 工作版本常驻内存，无I/O | eXtremeDB |
| **基于文件（FDB）** | 文件方式存储，被动式访问 | SQLite、Pocket Access |
| **基于网络（NDB）** | 通过移动网访问远程数据库 | — |

#### 嵌入式数据库 vs 数据库服务器 ⭐

| 对比维度 | 嵌入式数据库 | 数据库服务器 |
|----------|--------------|--------------|
| **运行方式** | 与应用程序**同一进程** | 独立守护进程 |
| **访问方式** | API（非TCP/IP） | JDBC/ODBC + TCP/IP |
| **部署** | 与应用程序一起发布 | 需独立安装部署管理 |
| **使用者** | 仅应用程序 | 允许非开发人员 |
| **数据控制** | 由应用程序控制 | 独立的访问控制 |

#### 典型产品对比

| 产品 | 类型 | 主要特点 |
|------|------|----------|
| **SQLite** | 文件型 | 无需安装、ACID事务、文件2TB、跨平台字节序共享 |
| **Berkeley DB** | 嵌入式 | 多语言API、管理256TB数据库、高并发 |
| **Firebird Embedded** | 嵌入式 | SQL-92/99标准、支持事务/存储过程/触发器 |
| **eXtremeDB** | 内存型 | 实时性强、最小化资源、代码体积小 |

#### SQLite 架构四子系统

1. **接口（Interface）**——C API
2. **编译器（Compiler）**——分词器→分析器→代码生成器（生成汇编代码）
3. **虚拟机（VDBE）**——解释执行字节代码，128个操作码
4. **后端（Back-End）**——B-tree（索引）+ Page Cache（页缓存）+ OS接口

### 2.4 嵌入式中间件 ⭐

#### 定义

处于**嵌入式应用和操作系统之间**层次的中间软件，主要作用是**屏蔽底层操作系统的异构性**。

#### 常用功能

网络通信、存储管理、数据处理

#### 两大典型中间件 ⭐⭐

| 中间件 | 标准来源 | 架构模式 | 技术特征 |
|--------|----------|----------|----------|
| **CORBA** | OMG（1991） | 对象请求代理（ORB） | 完整事务代理、客户端/服务器分离、软件总线机制、实时性强 |
| **DDS** | OMG | 发布/订阅 | 以数据为中心、丰富QoS策略、强实时、跨平台 |

#### 消息中间件两种模型

- **点对点（PTP）**：消息生产者→队列→特定消费者
- **发布/订阅（Pub/Sub）**：发布者→主题→多个订阅者

#### 分布式对象中间件三大技术

- OMG 的 **CORBA**
- Microsoft 的 **DCOM**
- Java 的 **EJB**

## 三、嵌入式架构设计方法 ⭐⭐

### 3.1 ABSD（基于架构的软件设计）

- **核心**：由业务、质量和功能需求的组合驱动架构设计
- **方法**：自顶向下、递归细化的软件开发方法
- **特点**：递归的、迭代的、逐步完善的；架构总是清晰的
- 适用于嵌入式系统（目标明确、用途单一、质量/可靠性要求高）

### 3.2 ADD（属性驱动的软件设计） ⭐⭐

- **核心**：以**质量属性场景**作为输入驱动架构设计
- **特点**：递归的模块分解过程，基于质量属性

#### 质量场景六要素

| 要素 | 说明 |
|------|------|
| **刺激源** | 生成刺激的实体（人/计算机） |
| **刺激** | 到达系统后需考虑的事物 |
| **环境** | 刺激发生时的各种条件 |
| **制品** | 系统或系统的一部分 |
| **响应** | 刺激到达后采取的反应 |
| **响应度量** | 对响应进行度量 |

#### ADD 七步开发过程

1. **评审输入**——确保输入可用/正确，确认架构驱动因子
2. **选择驱动因子建立迭代目标**——确定设计回合
3. **选择系统元素细化**——选取满足驱动因子的架构结构
4. **选择设计概念细化**——从架构模式中选择
5. **实例化元素、分配职责、定义接口**——决定分层数量，分配职责
6. **草拟视图、记录设计决策**——文字/图方式记录
7. **分析设计、评审目标、实现目的**——评判是否满足驱动因子

### 3.3 DARTS（实时系统设计方法） ⭐⭐

- **核心**：将实时系统分解为**多个并发任务**，定义任务间接口
- **起源**：RTSAD（实时结构化分析和设计方法）
- **适用**：工业控制、航空航天、轨道交通等强实时系统

#### 关键概念

- **RTSA（实时结构化分析）**：用**状态转换图（STD）**刻画系统行为特征
- **RTSD（实时结构化设计）**：通过事务和变换策略将DFD/CFD转换为程序结构图
- **任务结构化标准**：帮助将系统分解为并发任务
- **信息隐藏模块（IHM）**：封装数据存储

#### DARTS 五步开发过程

1. **用 RTSA 开发系统规范**——系统环境图（SCD）和状态转换图（STD）
2. **将系统划分为多个并发任务**——应用任务结构化标准
3. **定义任务间接口**——消息通信/事件同步/信息隐藏模块，进行时间约束分析
4. **设计每个任务**——使用结构化设计方法，划分为多个模块
5. **设计成果**——RTSA规范 + 任务结构规范 + 任务分解

#### DARTS 评价

| 优势 | 不足 |
|------|------|
| 强调并发任务分解，提供确认标准 | IHM 未完全封装（不如NRL/OOD） |
| 提供详细的任务间接口定义指南 | RTSA 阶段工作没做好则任务创建困难 |
| 强调任务架构图（TAD）的重要性 | — |
| 提供从RTSA到实时设计的转换 | — |

## 四、嵌入式系统软件架构案例分析

### 4.1 鸿蒙操作系统（HarmonyOS） ⭐⭐

**层次化架构（从下到上）：**

```
内核层（内核子系统 + 驱动子系统）
  ↓
系统服务层（4大子系统集：基本能力/基础软件/增强软件/硬件服务）
  ↓
框架层（Java/C/C++/JS 多语言框架 + Ability框架）
  ↓
应用层（系统应用 + 第三方应用，FA有UI/PA无UI）
```

**四大技术特性：**
1. **分布式架构**首次用于终端OS（分布式软总线/数据管理/任务调度/虚拟外设）
2. **确定时延引擎 + 高性能IPC**（应用响应时延降低25.7%，IPC性能提升5倍）
3. **微内核架构**（代码量仅Linux宏内核的1/1000，形式化方法验证TEE，CCEAL5+认证）
4. **统一IDE**（一次开发多端部署，方舟编译器静态编译）

### 4.2 GENESYS 跨领域架构

- **核心思想**：分离计算与通信，基于消息传输
- **两类构成**：构件 + 基础平台
- **三组服务**：领域无关（核心/选择）、领域专用、应用专用
- **四类构件**：硬件/软件、系统/应用
- **四类接口**：LIF（链接）、LI（局部）、TII（技术无关）、TDI（技术相关）
- **三级集成**：芯片级（IP核/NoC）、设备级（芯片）、系统级（设备）

### 4.3 物联网操作系统（FreeRTOS）

- **组成**：BSP驱动 + 内核 + 组件
- **四大特征**：内核尺寸伸缩性、内核实时性、高可靠性、低功耗

## 五、易混淆概念对比

| 对比项 | 区别要点 |
|--------|----------|
| MPU vs MCU | MPU 需外接存储/总线；MCU 单片化，集成度高 |
| DRAM vs SRAM | DRAM 需刷新、便宜；SRAM 无需刷新、快、贵 |
| RAM vs ROM | RAM 断电丢失（临时存储）；ROM 断电保留（永久存储） |
| 宏内核 vs 微内核 | 宏内核同一空间/性能好；微内核不同空间/移植性好 |
| 层次化 vs 递归模式 | 层次化基于概念抽象分层；递归基于重复包含关系分解 |
| EDF vs RMS | EDF 动态/按截止时间；RMS 静态/按周期 |
| 嵌入式DB vs DB服务器 | 嵌入式DB同进程/API访问；DB服务器独立进程/TCP/IP |
| 内存DB vs 文件DB | 内存DB 常驻内存/强实时；文件DB 磁盘存储/持久化 |
| CORBA vs DDS | CORBA 对象请求代理；DDS 发布/订阅、以数据为中心 |
| ABSD vs ADD | ABSD 由业务+质量+功能需求驱动；ADD 由质量属性场景驱动 |
| ABSD vs DARTS | ABSD 通用架构设计；DARTS 专注实时系统的并发任务分解 |
| 宿主机 vs 目标机 | 宿主机开发（通用平台）；目标机运行（嵌入式平台） |

## 六、核心公式/速记

```
任务三状态：就绪 ←→ 执行 → 阻塞 → 就绪

松弛度 = 截止期限 - 运行时间 - 当前时间

RMS 最优性定理：
  若一组进程不能由 RMS 调度 → 不能由任何静态优先级算法调度

存储管理五种方法：
  分区 → 分页 → 分段 → 段页 → 虚拟存储

任务间通信五种方式：
  共享内存 → 信号量 → 消息队列 → Socket → Signals

DARTS 流程：
  RTSA规范 → 划分并发任务 → 定义接口 → 设计每个任务 → 成果

鸿蒙架构四层：
  内核层 → 系统服务层 → 框架层 → 应用层
```
